# 別ツモ500ゲームを用いた追加学習と改善

状態：完了。3案を試し、最終案を追加500・従来500で比較したが不採用。
追加500で連鎖尾完成469→468、5連鎖以上417→415となり、完成優先を満たす改善を確認できなかった。
標準ロジックは試行前と同一へ戻した。新しい診断・測定手段と結果、実験コードは保存している。

## 条件

- 変更前：平坦さの評価を追加した `surface-20260922-v2` と同じコード。
- 追加集合：seed20260922、4色random、500ゲーム、最大20手、従来6初手分類。
- 最初の250ゲームで原因を調べ、改善案を作る。後半250ゲームの内容は変更を固定するまで調整に使わない。
- 従来集合：seed20260904の500ゲーム。閲覧済みの回帰集合であり、未使用データとは呼ばない。
- 推薦に渡す情報は盤面、CURRENT/NEXT/NEXT2、折り返しの色計画のみ。
- 成功定義、手数、ツモ生成、乱数状態への非アクセスを維持する。

「学習」は失敗例の分析・仮説・ロジック修正・同条件の再測定を意味し、
モデルの重みを訓練したり、特定のseedや手順をゲームへ暗記させたりすることではない。

## 調査する課題と採用基準

尾完成後に5連鎖へ進めない、色待ちが狭い、完成が終盤になる、高い谷や用途不明の余剰が増える局面を調べる。
Y→座布団→Lの方針、既存の低い接続・発火点伸ばし・5連鎖の即時発火を守る。

- 原因を説明できる一般的な変更に限定し、ゲームID・seedに応じた分岐はしない。
- 局面単体の改善を、全500ゲームの成功率改善と混同しない。
- 従来500と追加500で、連鎖尾完成・本線5連鎖以上の実発火が各70%以上を維持する。
- 70%だけを合格理由にせず、従来の完成率からの低下、谷・ちぎり・余剰・必要手数も比較する。
- 変更で悪化した局面も保存し、未解決の課題と分けて報告する。

### 不採用案

1. 高い盤面で左接続が空のときに骨格探索を省く条件を、無条件で撤廃する案。
   開発集合8番では既存の緑Yを壊す配置を避けたが、20手以内の尾完成を失った。
   既存の「左から尾をつなぐ」テストも失敗したため元へ戻した。
2. 未完成セルの受け口となる色数を、尾完成後も常時加点する案（v2）。
   開発250では尾229→231、5連鎖198→200だったが、既存の報告ツモで14手目の5連鎖を失った。
   平均値だけを理由に回帰を容認せず、不採用とした。テストの期待値は変更していない。

### 最終試験版（v3、不採用）

成立する骨格に対して、各列で次に積める未完成セルの**異なる色数**を1色12点、最大48点加える。
埋まった列、余剰の上、別色の支持の下にある色は数えない。
これは合法な組ぷよ配置数や将来のツモの予言ではなく、構築中の色の受け口を広げる小さい補助評価。
骨格1セル進捗100点・Yと他の型の差80/90点より小さくし、折り返し・実発火の制約は変えない。

**折り返し＋教材尾の必要セルが埋まった後は加点をやめる。**
完成後まで受け口を残そうとして、5連鎖への伸ばしを遅らせないため。
既存のY字報告ツモ、低い本線の接続、左端の伸ばし、実発火優先のテストは通過した。

### 評価軸別の判定

| 軸 | 試験版の判定 |
|---|---|
| H1 構築順 | 低い支持へ回す改善例はある。既存の初手回帰は維持。全局面での改善は未確認 |
| H2 両方の活用 | 追加500の残り・参加率は改善、従来500は小幅悪化。途中ぷよの全役割は未評価 |
| H3 尾の継続性 | Y・座布団の個別回帰は維持したが、両500集合の尾完成率が低下 |
| H4 高さ・操作 | ちぎりと平均段差は改善。追加500の高い壁の谷は悪化。実操作時間は未評価 |
| H5 発火点伸ばし | 既存回帰は維持。伸ばし単独の成功率・一般的な多重は未評価・未実装 |
| H6 説明可能性 | 代表例の理由は整理。全手順の説明UI・定量評価は未実装 |

**結論：v3は採用しない。今回、標準推薦を置き換えられる品質改善は確認できなかった。**
追加500の変更前で5連鎖未達だった83件の内訳は、尾完成後未発火59、尾未完成12、
折り返し未完成6、3〜4連鎖発火6。実際に撃てる5連鎖の見逃しは0件だった。
尾完成後未発火59件のうち22件は、仮想発火で5連鎖となる時点が19〜20手目。
発火ボタンを押す判断より、完成までの色待ちと伸ばしの手順が調査対象となる。

次の仮説は「色の種類数」だけでなく、支持を含めて**組ぷよの2個を実際に使える配置**を比較すること。
必要色を何段下に残すか、谷を作らず接続する代案、尾完成から5連鎖までの進行を併せて検証する。
これは次の検証方針であり、実装済み・改善実証済みとは扱わない。
今回の後半250件は閲覧済みになったため、次回の未使用検証集合には再利用しない。
