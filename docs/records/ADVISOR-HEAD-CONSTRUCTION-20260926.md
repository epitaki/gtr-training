# 土台完成前から余る色を横の発火点仕込みへ使う

日付：2026-09-26。対象は非発火ガイド。採点範囲・満点条件・供給・20手上限は変更しない。

## 報告と変更点

2026-09-25T00:37:24.552Zの利用者報告は、土台が100点の一方、2列目の4〜6段目に青が縦3個余るもの。
記録11手を物理再生して一致を確認した。横3を作る別手順も同じ実ツモで成立する。

- 7手目の青青を1〜2列目4段目に横置きする。
- 11手目の緑青を3列目に下から緑・青と置き、横3にする。土台5の完成は両版とも11手目。
- 12手目の赤緑で1列目に緑のキーと赤の相方を置く。ここまでは一切消去しない。
- 12手目後の全盤面に単ぷよを仮置きした接続見込みは、旧版5連鎖・余り4個、新版6連鎖・余り0個。
  発火済みの実績、未知のツモでの成功率、平均余りの達成とは扱わない。

再利用用の[簡潔な手順データ](../research/head-construction-feedback-20260926.json)と、
[実供給での前後再推薦](../../benchmarks/results/head-construction-v3-feedback-20260926.json)を保存した。
記録された配置は当時の画面推薦と同一だと決めつけず、現行・凍結版の再計算と分けている。

## 推薦の条件

1. 基本形を別色で塞がないこと、非消去、現在手の土台5完成を維持する。
2. 新しく発火口を埋める仕込みは、従来候補と**配置後の評価範囲内が完全に同じ**場合に限る。
   頭のために土台進行を犠牲にせず、左の2列に実在する同色2個を横に使う。
3. 骨格探索に非発火ガイド専用のキー待ち対応を追加する。実際の余剰セルを残したまま候補骨格を仮完成し、
   横3・左右L字の不足セルとキーが上から置け、元の土台が順番どおり消えることを検証する。
   この仮完成は構築可能性の条件であり、色が供給された・土台5完成済みとは数えない。
4. 仕込み開始後はキー待ちを理由に骨格探索から除外しない。見えるCURRENT/NEXT/NEXT2だけで継続する。
5. すでに頭を仕込み、現在手で土台5が完成する場合は、元の土台へ戻れる接続を優先する。
   回収と必要数が同等なら、最大列高・ちぎりで低い方を選ぶ。100点を維持するためだけにL字へ上積みしない。
6. 旧実発火ベンチマーク用の探索は既定のまま。新しい許可は明示した非発火ガイドだけで使う。

この変更で横3に常時加点したり、発火口を必ず埋めたりはしない。キー閉塞、1個だけの仕込み、
元の土台を先に消す接触、上の3連結だけで接続がないものは有効な仕込みにしない。

## 土台点と伸ばしを区別する

今回の横3は、3列目4段目の青が採点範囲に入るため、従来どおり土台93点。
縦3の100点より表示点が低くても、土台5を保って青を回収へ使える手順として選択できる。
範囲内の青を都合よく採点から削除したり、上部の6連鎖を土台点へ足したりはしない。
これは満点定義の変更ではなく、完成と伸ばしを分けた推薦判断の変更。

### 連鎖尾完成の見落とし補正

測定時の旧判定では尾完成が479→468件だった。新しい横3・左高L字を含む頭を、
古い固定発火口／限定頭だけの判定が認識できず、実在する尾を未完成にしていた。
`GuidedTail.ts` は、実際に尾の必要セルがすべてあり、評価範囲内に3連鎖以上が成立し、
その元セルの消去順へ戻る全盤面接続またはキー待ち仕込みを証明できる場合に尾完成とする。
不足している尾セルを仮に足したり、キー待ちを実発火に数えたりはしない。

旧版・新版の全保存手順の供給と物理を再検証し、この同一判定で両方を再集計した結果が上表の479→480。
新版は旧判定の468件に、見落としていた12件が加わる。旧版は479件のまま。
これは推薦の追加実行ではなく判定の補正。測定当時のJSONを上書きせず、旧値も別項目に残した。
補正は画面と今後の継続ガイド計測へ接続し、旧実発火探索の内部判定・推薦手順は変更しない。
分割結合は判定定義の混在を拒否し、前後比較も保存当時のフラグ同士ではなく共通判定で比較する。
