# 青緑の上下：低い本線と上側の伸ばし余地

状態：2026-09-22、限定した候補拡張を推薦ロジックへ反映。固定500ゲームの検証済み。

## 入力と利用者の意図

- 診断：capturedAt=2026-09-21T18:18:57.249Z、randomState=847661216、9手目。
- 入力：上9行は空。下4行は次のとおり。R=赤、B=青、Y=黄、G=緑。
- CURRENT=BG、NEXT=RR、NEXT2=BB。折り返しA=緑、B=黄。

```text
.YB...
GYRB..
GGYRR.
YYRBB.
```

ガイドは5列目へ下から緑→青を推薦。利用者の提案は下から青→緑。
連鎖数を増やすだけでなく、下から4段目付近を次の伸ばしに使うため、
低いところで本線に参加できる配置を優先したい、という補足を受けた。

## 物理検証と原因

修正前のコードでも5列・下向き（下から緑→青）が1位、101830.58504390126点。
5列・上向き（下から青→緑）は-99967点。`FiveChainPlanner.rank`では後者が候補に入っていない。
列ごとの固定配色との不一致で探索から除かれ、`PlacementAdvisor`で骨格候補と約20万点の差が付く。
候補の低評価は「本線につながらない」という物理検証の結論ではない。

両案とも今回の配置直後には消えない。発火点へ緑を補って検証すると両方4連鎖。
青が下ならその青が4連鎖目へ合流し、緑が下なら追加した青は緑の上に残る。
試験用の緑緑を1列目へ縦置きする場合は、青下が19個消去・緑1個残り、
緑下が18個消去・青緑2個残りとなる。
この緑緑は見えている次ツモではなく、消える順序を比較するためだけの仮定。

NEXTの赤赤・NEXT2の青青について、途中消しを起こさない全合法配置を列挙しても、
この2手の後に標準発火から成立する本線はどちらの上下でも最大4連鎖だった。
この結果は未知ツモを含めた将来の伸ばしや優劣の証明ではない。

## 評価へ反映する原則

今回、列の高さはどちらも4段で同じ。単純な高さ減点を強めても違いを表せない。
低い層での実際の本線参加と、上側の伸ばし・支持の役割を比較する必要がある。
青を下で回収し、上の緑を次の接続に使える配置は、その比較に入れるべき候補である。
緑の先の連鎖が既に完成した、あるいは常に最善であるとは断定しない。

[品質基準](../specs/GTR-QUALITY-CRITERIA.md)に基づき、固定骨格外の候補を比較に残す仕組みを追加した。
以下の項目を回帰確認の対象とする。

- 報告盤面と色替え：上下が変わっても連鎖数だけでなく参加ぷよを追う。
- 本線を崩す低配置、上部の支持が必要な配置、現在または見えるツモでの5連鎖を逃す配置を優先しない。
- 初手の折り返し、Y→座布団→L、限定発火点伸ばしを維持する。
- 同じ500ゲームで連鎖尾完成・実発火・2/3列の残り・ちぎり・計算負荷を比較する。

## 実装範囲

`LowerChainInsertion.ts`で、元の5連鎖骨格の列途中に1個を加えた形を物理検証する。
元の各ぷよについて、列内の押し上げ分を補正して、全て同じ連鎖段階で消えることを照合する。
追加した1個も本線に参加し、配置時に消えず、発火口と出現位置を塞がない形だけを許可する。

探索で認めるのは、3〜6列の下3段以内で、教材の連鎖尾・支持より上にある1個。
現在の盤面で実際に4連鎖目以降に参加することも必要。コア・尾そのものはずらさず、
頭伸ばしの仮補充でしか回収できないセルは新規候補の根拠にしない。
1骨格につき1個までの限定実装であり、任意形の自由な圧縮や一般的な多重には対応していない。

追加セルを「5連鎖へ1個進んだ」として100点加算する試行は既存の発火を遅らせたため不採用。
既存の進捗には含めず、回収できる余剰として扱う。今回置くぷよを下で回収できる場合だけ
余剰1個分相当の8点を与える。先読みで仮に置く将来の回収だけにはこの8点を付けない。
追加候補には既存のちぎりコスト（段差1段につき8、最大24）も適用し、
低い接続を理由に不要なちぎりを選ばない。新しい挿入候補を使わない既存経路の操作点は変えない。
成立した本線発火の終端点には、これらの調整を加えない。

報告盤面の推薦は5列・上向き（青が下・緑が上）になった。
色替え4通り×軸の入れ替え2通りでも同じ配置を選ぶ。
この1手の連鎖数は依然4であり、ガイド改善を「5連鎖になった」とは報告しない。

直前の95.4%・82.6%は比較元の500ゲームの値。今回の測定結果とは分けて記載する。
