# GTR完成を優先した雪崩・鶴亀の余剰回収

日付：2026-09-24。採用：v2の限定評価。結果採点ではなく、実際の配置ガイドを変更した。

## 目的と資料

GTRに使えない色を2・3列や右端へ置くだけにせず、本線からの落下を使って回収する。
完成・実発火が優先。長い連鎖や高い列そのものにボーナスを与えない。
土台のY字→座布団→L字という選好と、雪崩に使うL字部品は区別する。

- [雪崩の調査・利用者指定のぴろぷよ解説](../research/GTR-AVALANCHE-RESEARCH.md)
- [発火点伸ばしの調査と追加指定資料](../research/GTR-HEAD-EXTENSION-RESEARCH.md)：動画は公開字幕と2場面の比較図を確認。一般的な多重の実装ではない。
- [雪崩1本・鶴亀3本の保存済み教材譜](../../benchmarks/human/piropuyo-tail-20260924-v1.json)：全配置を物理再生するテストを追加。試合4本や唯一の正解ラベルには数えない。

## 実装したこと

`TailCascadeRecovery`は共通シミュレーターの消去履歴から、元の位置・色・落下後の位置を追う。

1. 元の5連鎖骨格の全ぷよが、追加ぷよのある盤面でも元と同じ消去段で消えることを確認する。
2. 本線の消去、またはそこにつながる消去によって支持が外れ、直後の段で落下接続した連結を確認する。
3. 4〜6列の骨格より上にある追加ぷよを対象とし、独立した別消し・孤立した高積みを回収としない。
4. 基本雪崩の3列1・1・2（反転を含む）と、その他の鶴亀型の落下回収を記録上で区別する。形名による倍率は付けない。
5. 同色の本線に直接合流する従来の回収数と、別の連結として消える追加回収を二重計上しない。

適用するのは、呼び出し時点で教材尾が完成し、現在またはCURRENT/NEXT/NEXT2の探索先で
骨格全体が実際に埋まった場合。回収セル1個8点、上限16点で、骨格1セルの進捗100点より小さい。
未完成骨格を都合のよい色で仮補充しただけでは回収加点しない。
発火色を仮に加える検証は構築上の見込みであり、実ツモによる発火成功として数えない。

既存の左端の発火点伸ばしは併用するが、頭の仕込みへこの追加点を重ねない。
安全な骨格進行がある場合は新しい頭を始めず、完成済み5連鎖の発火口を新しい待ちで塞がない。
実ツモで今5連鎖を打てる場合は、雪崩の追加完成を待たず実発火を優先する。

`PlacementAdvisor.getAdvice` → `GuidedPracticeScene.updateAdvice` → 配置ゴーストに反映される。
雪崩用の専用コーチ文は追加していない。最小5連鎖土台の100点条件や成功指標も変更していない。

## 試行と採否

- **v1（不採用）**：尾が完成していれば、骨格全体が未完成でも仮完成時の回収を加点した。
  50ゲームでは成功数を維持したが、既存の2つのツモ列×4配色のテストで予定手数内の5連鎖が崩れた。
  500ゲームでは5連鎖の成功総数は同じでも、game159・253を失敗化し、game229・448が新たに成功した。
  余り平均7.92→7.59だけを理由に採用しない。
- **v2（採用）**：加点を骨格全体が現在または見えている組で完成する場合に限定した。
  上記テストを回復し、500ゲームの尾完成・5連鎖成功の個別集合も維持した。

## 検証と対象外

- 雪崩、鶴亀、2層の落下接続、色置換、独立消し、暴発、加点上限、実発火優先をテストした。
- 実際の推薦器と画面の配置ゴーストを接続し、雪崩・鶴亀の着地点が反映されることをテストした。描画エンジンのみ代替しており、利用者のプレイ中タブは再読み込みしていない。
- 最終状態の全47ファイル・639テストが通過。型検査・測定スクリプトの型検査・配布用ビルドも通過。ビルドには既存のサイズ警告が残る。
- 広い色受け、未完成雪崩の柔軟性、一般的な多重、頭と尾の任意の同時延長は未実装。
- 教材の再生と、推薦が同じ長連鎖を構築できることは別。今回の教材譜は推薦の実行時データとして使用しない。
