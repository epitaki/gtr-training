## 再現と修正

13手目、CURRENT青青、NEXT緑緑、NEXT2赤緑。下6行は次のとおり（上7行は空）。

```text
..R...
.YB...
.RBYY.
BYGRR.
BBYGGG
YYGBBR
```

旧処理は全盤面で消去・重力を解決した後、余りだけ範囲内に限定していた。
3列目の範囲外の青が4連鎖目、赤が5連鎖目に参加しており、土台の成績に上部が混入していた。

評価用コピーの作成時点で範囲外を除去する。評価範囲は1・2列目11〜13行、3〜6列目10〜13行。
範囲外からの落下・同色の合流・余りへの混入を避ける。仮想発火1個だけを別途追加する。
採点と結果画面の範囲定義は `EvaluationRange.ts` を共有する。

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| 土台評価の連鎖数 | 5 | 3 |
| 土台評価の余り | 3 | 8 |
| 土台スコア | 85 | 71 |

実プレイで青青を左端に置けば引き続き5連鎖。推薦の物理判定は全盤面のままとし、
土台評価と別のAPIへ分けた。土台の仮想発火成立は、実際の発火口が空いているという主張ではない。

## 評価スキル

「評価skillsも見直して」という依頼について、GTR品質評価の手順と解釈した。
既存の個人スキルは汎用コードレビュー2種だけだったため、既存の適用範囲を広げず、
`gtr-quality-evaluation` を個人スキル領域 `C:/Users/sunpe/.codex/skills/` に新規追加した。

`skill-creator` と OpenAI Docs の手順を利用。
名前・説明・適用条件・作業範囲を明確にする構成は [OpenAI公式のスキル作成資料](https://developers.openai.com/plugins/build/skills) に従った。
土台と実発火の区別、範囲外の不変性テスト、100点率・余りの分母、同条件比較、
人間らしさと悪化例、未実装指標を達成済みにしないことを記載した。

`quick_validate.py` は通常・同梱Pythonの両方で PyYAML がなく実行できなかった。
代わりに Bun のYAMLパーサーで本文のフロントマターとUI設定を読み、名前、文字数、許可キー、
未完プレースホルダー、スキル名入り既定プロンプトを検証して成功。意味内容は独立3レビューでも確認した。
Python検証器の完走や、独立エージェントによる実運用シナリオ試験まで完了したとはしない。
