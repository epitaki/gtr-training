# プロフィール画像変更（2026-10-10）

状態: 完了。右上アカウントモーダルで画像変更と初期状態への戻しを提供する。

JPEG・PNG・WebPを20MiBまで受付け、中央を正方形に切り抜く。最大256×256px（小さな画像は拡大しない）、WebP品質0.85。64メガピクセルを超える画像・破損画像はエラー。ブラウザで変換後に送信し、最大256KiB。

Supabaseの非公開avatarsバケットにユーザーID/ランダムUUID.webpで保存。profiles.avatar_pathに本人のパスだけ保存し、表示時は期限1時間の署名付きURLを生成する。本人のみSELECT/INSERT/DELETEを許可し、他人のパスや権限列を変更できない。プロフィール更新失敗時は新画像を削除し、成功後は旧画像を片付ける（ネットワーク障害・ログアウト後は削除を試みる）。既存の表示名・認証・ゲーム処理は保持する。

検証: 縮小・異常入力・保存失敗・アカウント切替の単体検証、SQL権限検証、クラウドで実画像変更/再読込/リセット、基本型検査/全テスト/ビルド。

検証記録: docs/reviews/PROFILE-AVATAR-VALIDATION-20261010.md。クラウド適用済み。ローカルDocker停止中につきローカル適用は起動後に実行する。

## 2026-10-15 保存量の上限

リリース前監査で、所有者ごとのトランザクションロックを使い、avatarsの所有パスへのINSERTを最大10オブジェクトまでに制限した。1ファイル256KiBとWebP・非公開/本人制約は維持する。削除で枠が戻る。Storageのファイル操作はAPIを使い、SQL関数はメタデータの照会だけを行う。旧画像の掃除失敗が積み重なる場合は参照中の画像を保護して不要分を整理する。[監査](../reviews/PRE-RELEASE-SECURITY-AUDIT-20261015.md)。
