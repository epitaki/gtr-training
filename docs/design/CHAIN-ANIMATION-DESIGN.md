## 1. 目的と実施順

今のアプリには連鎖の計算があるが、全段階を同期処理してから描画するため、消去と落下の途中が見えない。
まず既存画像で「何が消えて、何が落ちて、次に何が消えたか」を見せる。その後、独自の8bit風素材と個別の動きを追加する。

課題はHabiticaで管理する。削除済みの `tasks/` は復活させない。

対象はガイド付き練習とGTRスコアアタック。以下は変えない。

- 連鎖の物理、スコア計算、土台の採点範囲、推薦順位、ツモの乱数・順序。
- 「ガイドは完成後も発火を勧めず、連鎖を伸ばす」という方針。利用者が実際に消したときに演出する。
- 評価ボタンの仮想発火と実プレイの区別。採点用の盤面を実盤面へ反映しない。
- 同じ消去段階で成立した複数グループ・複数色は同時に消す。1個ずつ消して連鎖数を増やさない。

効果音・ボイス、対戦・おじゃま、紫色の追加、UI全面刷新、仮想発火の鑑賞モードは今回の対象外。

### 本アプリへの採用案（観測事実とは別）

1. Aでは「対象の短い強調 → 同段の消去 → 落下 → 次の段」を優先する。
2. 段数表示を消去開始に合わせる。色や光だけでなく「何連鎖目か」を読めるようにする。
3. B・Cでは、胴体の接続と個々の顔を両立し、落下・着地・消滅で短い独自フレームを使う。
4. 動画の派手な光・顔・輪郭をそのまま写さず、盤面を読みやすい小さな演出にする。
5. 下記の時間は学習用の初期調整値であり、動画から測った値ではない。

## 4. 責務とデータ

[現行アーキテクチャ](../PROJECT-STRUCTURE.md)に従い、計算側へPhaser・待機・演出時間を持ち込まない。
既存の `resolveChains()` の戻り値と通常呼出しの軽さを保つため、公開窓口は
`resolveChainsWithTrace()` を追加する案とする。内部の消去・重力ループは共用し、第二の物理エンジンは作らない。

```text
core/ChainSimulator ── 計算結果＋任意トレース ──> scenes/（1手の進行制御）
                                                      │
                                                      └─> rendering/ChainPlayback
                                                             └─> PuyoBoardRenderer
```

以下は追加・変更予定。`ChainTrace`・`ChainPlayback`・`PuyoBoardRenderer` は新規、
`ChainSimulator`・`VisualConfig`・両シーンは既存ファイルの拡張とする。

| 予定箇所 | 責務 |
|---|---|
| `core/ChainTrace.ts` | 表示にも使える論理的な段階データの型。画面座標や時間は持たない |
| `core/ChainSimulator.ts` | 既存処理と同じループ内で、要求された場合だけトレースを採取 |
| `rendering/ChainPlayback.ts` | トレースを表示段階へ展開し、進捗・停止・取消・完了を管理 |
| `rendering/PuyoBoardRenderer.ts` | 盤面上の個体と画像の対応、接続、移動、消滅。両モードから利用 |
| `rendering/VisualConfig.ts` | 演出時間・表示倍率など。物理パラメーターと区別 |
| `scenes/GuidedPracticeScene.ts` / `PuyoGame.ts` | 入力・ツモ・スコア・履歴・ガイド・確定処理との接続 |

### 表示トレースの最小構成

- `initial`：組ぷよを実際の固定位置へ置いた直後の盤面。最初のちぎり落下より前。
- `stages`：`gravity` と `clear` の列。
  - `gravity`：各個体の `id / from / to` と落下後の盤面。初回のちぎりも同じ形式。
  - `clear`：`chainIndex`、対象の `id / position / color` と消去直後の盤面。
- 各盤面はセルの色と個体IDを対応付けた独立したスナップショット。後続計算で変化しない。
- `result`：現行と同じ最終盤面・連鎖数・消去数・全消し・消去履歴。

個体IDはトレース開始時の各占有セルに付け、重力とともに移動させる。
再生の実行番号＋開始セルを使えば、その再生内で同色の2個を取り違えない。
既存の `origins` は評価で `null` などの意味を持つため、表示IDとして上書き・再解釈しない。
通常の推薦・ベンチマーク呼出しではID盤面・中間スナップショットを生成しない。

移動も消去もない場合は空の段階列を許す。移動ゼロの重力段階は表示上スキップする。
同時消しは1つの `clear` に全対象を格納し、グループ数を連鎖数にしない。
座標は既存どおり左上原点、6列×13行。画面外／隠し行の見え方で物理判定を変えない。

## 5. 1手の進行と確定

```text
操作中 → 固定位置の検証・解決結果の計算
       → 初回落下／着地
       → 対象強調 → 同段消去 → 落下／着地 ─┐
                    ↑ 次の消去があれば ────┘
       → 一度だけ確定 → 次ツモ／ゲームオーバー
```

### データを変更する境界

1. 固定の瞬間に二重開始を防ぐ `resolving` を立てる。2個とも盤面内・空き・別セルであることを検証する。
2. 複製盤面へ2個を置いて計算する。実盤面・確定得点・履歴・ツモ乱数はまだ変更しない。
3. 操作中の2個を隠し、描画所有権を再生器へ渡す。通常の盤面差分描画・既存の消去演出・ゴースト更新は停止。
4. 中間表示はトレースだけから作る。`gameField` は前の確定盤面を保ち、外部へ途中のスナップショットを返さない。
5. 終了時に同じ実行番号・未取消・未確定であることを確認し、最終盤面を反映する。
6. 消去数に応じた既存得点、GTR処理、ガイドの手順記録を一度だけ反映する。
7. 現行の順番でゲームオーバー判定・次ツモ供給・乱数状態・履歴・推薦を更新する。
   次ツモを生成しないゲームオーバー分岐も現行に合わせる。
8. 入力の押しっぱなしを解除待ちにし、落下／移動の時刻を更新して操作へ戻る。

再生中の連鎖番号は表示用の情報。得点は完了時にまとめて確定し、段階表示のたびに加算しない。
0連鎖でも初回のちぎり・着地を表示できる。連鎖番号は出さず、長い消去待ちを挟まない。

### 再生器の時間管理

初版は `update(delta)` 駆動の段階プレイヤーとし、チェーンを `setTimeout` の列で構築しない。
移動・拡縮・透明度・コマを同じローカル経過時間から描画すれば、テストで任意の時間を進められる。
`pause(reason)` / `resume(reason)` は停止理由の集合を使い、ポーズ解除が別の停止理由を消さない。
連鎖に属する演出はこの再生器で時間を管理し、独立して動くTweenを混ぜない。
背景化・復帰の大きなdeltaで全連鎖を飛ばさないよう、復帰時の時刻リセットとdelta上限を設ける。

暫定値：対象強調120ms、消去180ms、落下90〜300ms（距離依存）、着地80ms。
落下する個体は同時に動き始め、全員の着地後に次段へ進む。不要な段階は省く。
Aは単純な移動とフェード、Cは同じ段階へ独自フレームを割り当てる。
この値は015-Aの実画面で読みやすさを見て調整する。原作と完全に同じ速度を目標にしない。

## 6. 入力・取消・報告の方針

| 操作／イベント | 再生中の方針 |
|---|---|
| 移動・回転・落下 | 受け付けない。次の組ぷよ向けにも予約しない |
| Pによるポーズ | ガイドの既存機能に接続。再生と入力をともに止め、同じ途中時刻から再開 |
| ガイドの巻き戻し | 未確定の1手を取り消し、その手の開始状態へ戻す。確定済み履歴を余分にpopしない |
| 再生完了後の巻き戻し | 現行どおり確定履歴の1手前へ戻す |
| やり直し・メニュー・シーン終了／破棄 | 先に再生を取り消し、画像・粒・段数表示・一時データを破棄。完了処理は呼ばない |
| F/Gなどの表示・落下設定 | 初版は再生中変更を受け付けず、終了後に操作可能と案内。連鎖中の自動落下は元々行わない |
| 評価・結果表示 | 再生完了まで受け付けない。仮想評価と実解決を混ぜない |
| R／共有ボタン | 「連鎖アニメーション中です。終了後に共有できます」と返す。自動で早送り・確定しない |
| タブ非表示／復帰 | 再生を一時停止し、表示復帰でその理由だけ解除。ゲームのPポーズは維持。入力と落下時計はリセット |
| 再現URLの読込 | 新規シーンの安定状態として読込。前の再生を引き継がない |

スコアアタックには現在ない巻き戻し・Pポーズをこの作業で追加しない。既存操作があるモードだけに接続する。

### 巻き戻しの保存点

ガイドのツモ出現時（初期化・再現復元・巻き戻し復元を含む）に、深いコピーで
`turnStartSnapshot` を保持する。落下直前のペア座標ではなく、当該手の開始状態を保存する。
再生中の取消では盤面・3組・得点・GTR値・乱数をそこへ復元し、まだ追加していない手順記録は削除しない。
既存 `GameHistory.rewind()` を呼ぶのは通常の確定後巻き戻しだけ。

### 報告との整合

現在の再現データv1は、消去途中の画像や再生経過時間を表さない。
Aでは形式を変えず、安定した状態でだけ報告パネルを開く。
再生中の要求は新しい報告不可イベント（理由 `chain-resolving`）でReact側へ伝え、短い説明を表示する。
READYイベントや報告用の時計停止は実行しない。キーボードRも同じ扱いにする。
パネルを開いたあとは従来どおり盤面を固定し、共有文・画像・再現URLを同じ状態から作る。
演出そのものの途中報告が必要なら、再生トレース付きの別形式を後続で設計する。

### 取消とエラー

毎回の再生に単調増加する実行番号を付け、取消時に無効化する。
古い完了通知やイベントが遅れて届いても、盤面・得点・乱数へ作用させない。
シーンのSHUTDOWNとDESTROYは、両方呼ばれても安全に後始末できるようにする。
全シーンのTween／画像をまとめて破棄せず、当該再生が所有するものだけを処理する。
トレース不整合などで再生不能なら、未確定手を戻しエラーを示す。半端な盤面や二重確定で続行しない。

## 7. 独自8bit風素材（015-B）

利用者の添付スプライトシートは雰囲気と動きの参考のみ。
切り抜き、トレース、色替え流用はせず、輪郭・顔・陰影・フレームを独自に制作する。
赤・緑・青・黄の4色。透明背景、少数色のパレット、色だけに頼らない顔の違いを設ける。

### サイズと表示

- 盤面：24×24pxの原画を48×48pxへ整数2倍。原点はセル中央、足元を一定にする。
- 現行の `CELL_SIZE - CELL_GAP = 47px` への縮小はピクセル素材では行わない。
  透明余白を原画側へ持たせ、物理セル48px・盤面座標・衝突範囲は変えない。
- NEXT：同デザインの12×12pxミニ原画を36pxへ3倍、NEXT 2は24pxへ2倍。
  NEXT 2の現行26pxの配置枠は維持して中央に収める。パネル寸法は変えない。
- 教材図：8×8px専用原画を16×16pxへ整数2倍。現行18pxセル内に収める（015-Bのコード確認で具体化）。
- 画像テクスチャだけ補間を無効化し、UIの文字まで一括で荒くしない。移動中も描画位置をピクセルに揃える。
- 消滅の粒は別画像／別表示物とし、元のセル画像の余白を大きくして位置をずらさない。

### 必要な状態

| 状態 | 初期の素材案 |
|---|---|
| 待機 | 基本1枚。常時揺らし続ける演出は初版では不要 |
| 連結 | 上・右・下・左の4bitマスクで16状態。胴体＋独立した顔を組み合わせる |
| 接続成立 | 2コマ程度の短い形のなじみ。4個未満の接続も表示する |
| 落下 | 通常→少し縦長の2コマ。個体IDに対応付ける |
| 着地 | つぶれ→戻り→通常の3コマ。過度にはみ出さない |
| 消滅 | 明るくなる→小さく割れる→粒の3〜4コマ。対象外の色は変えない |

フレーム名は例として `red/idle`, `red/connect/0..15`, `red/fall/0..1` のように統一する。
透明背景・原点・色・状態・コマ番号・表示時間の対応表を残す。
制作データと出力PNG／アトラス／対応表は同じ版で管理し、画像だけ残して再編集不能にしない。

提案配置は `assets/puyo/source/`（制作データ）と `src/assets/puyo/`（実行時素材・対応表）。
生成画像を採用する場合もピクセル寸法・透明背景・全フレームの位置を検査し、ゲーム内48pxで確認する。
素材制作にはimagegenスキルを使う。015-Bの原画・加工・検査とレビュー記録は [素材契約](PUYO-PIXEL-PRODUCTION.md) と [開発フロー](../development/ASTRA-SOL-DEVELOPMENT.md) に残す。

## 8. 接続・個体アニメーション（015-C）

同色の上下左右に隣接する**静止した実ぷよ**だけを連結する。斜め・別色は接続しない。
操作中ペア、NEXT、半透明ガイドは盤面の接続判定へ加えない。
落下対象の接続表示は移動開始前に外し、着地した確定位置で再計算する。
同色が同じセルへ入れ替わっても、色差分ではなく個体IDから移動を再生する。

落下距離の異なる個体はそれぞれの着地点まで動かし、着地済みの個体を巻き戻して動かさない。
全対象の落下・着地が終わるまでは次の消去へ進まない。
消去する個体は同段で同期するが、粒の配置を変えることは可能。
その見た目の乱数にツモ生成用乱数を使わない。視覚テストでは固定値を使う。

## 9. 検証と受入条件

### A：計算と順次再生

- トレース有無で最終盤面、連鎖数、消去数、全消し、既存 `clearSteps` の内容・順序が一致。
- 0・1・2・5連鎖、横置きのちぎり、複数色同時消し、同色別群同時消し、全消し、出現口閉塞。
- 消去前・消去後・落下後の各盤面、移動元／先、IDの唯一性、入力の非変更、スナップショット間の非共有。
- 同色の縦列が落下する場合も、個体を消去／作り直しと取り違えない。
- 決めたdeltaを与え、段階の順番・ポーズ時の不変・完了1回・取消後の確定0回を自動検査。
- 各段階でポーズ／復帰、巻き戻し、リセット、終了、報告要求、タブ切替を行う。
- 0連鎖の即時完了でも二重の次ツモ生成をしない。長押し入力を次手へ漏らさない。
- 再生あり／従来の同期解決で、同じ操作列の確定盤面・得点・GTR値・履歴・次3組・乱数状態が一致。
- ガイドでSPACEを押しても実盤面は消えず、推薦に自動発火が追加されていない。
- 型検査・全体テスト・ビルド。ヘッドレス計測に表示用データや時間待ちを混入させない。
- 両モードのブラウザ実操作で「1段の消去 → 落下 → 次段」が見え、次ツモが途中に出ないことを確認。

### B：素材

- 4色の待機・全接続マスク・落下・着地・消滅について寸法、透明背景、原点、名前の欠落を検査。
- 通常48px、NEXT／NEXT 2、教材の小さい図、半透明ガイドで色と顔と接続を識別できる。
- 輪郭がにじまず、アトラスの隣フレームが混ざらず、接続境界に意図しない隙間が出ない。
- 利用者が基本の見た目を確認するまではCの見た目を最終確定しない。

### C：統合

- 16通りの隣接、2／3／4個以上、斜め・別色、複数色の落下、異なる距離、途中消去の見た目を確認。
- Aと同じ計算不変性・取消テストを再実施。装飾の追加で消去順やツモを変えない。
- 連続した再生と取消で画像・イベント・一時データが増え続けず、残像・二重生成・破棄後の更新がない。
- 動画やスクリーンショットで、配置・落下・消去・次ツモの代表場面を残す。計測値と目視確認を区別する。

## 11. Astraによる実装前確認（2026-09-26）

利用者がAstra設計→Sol実装→Sol独立レビュー3件→Astra確認の運用を承認。
`gpt-6-astra` の設計担当が本書と現行コードを確認し、015-Aの実装方針を以下のように具体化した。

- 最初の盤面には `PuyoPairManager.getRotatedPositions()` の実接触位置を使う。
  `simulateLanding()` は横組を各列の最終位置へすでに分離するため、初回ちぎり表示の開始位置には使わない。
- 表示用個体IDは開始セル番号と再生実行番号で識別し、既存の評価用 `origins` と独立させる。
- `ChainPlayback` はPhaser非依存でテスト可能にし、完了は初回の明示update以降に確認する。
  コンストラクターから完了通知して未登録の取引を確定しない。
- Aでは現行の47px画像・48pxセルを使う。24px原画への変更はB・Cまで行わない。
- ガイドは消去得点→手順記録→既存の次ツモ処理／履歴→ガイド更新。
  スコアアタックは消去得点→最終盤面で `checkGTR()` を1回（0連鎖でも実行）→既存の次ツモ処理。
- ガイドの供給は `PuyoPairRandom`、スコアアタックは `createValidTwoHandCombination().pair1`。
  モードの生成経路を統一・置換しない。再生処理は乱数を消費しない。
- 既存スコアアタックの装飾粒もグローバルな `Math.random` を消費するため、古い装飾を含む全乱数呼出し列まで
  一致すると主張しない。供給関数の回数・順序・ルールを維持し、ガイドの保存乱数状態は厳密に比較する。
- タブ復帰後の「キーを離すまで待つ」処理で再生まで停止させない。操作だけを抑制し、停止理由がない再生は進める。
- 再現URLから開始した手の巻き戻し保存点は、読込時の実ペア位置・向きとする。勝手に出現位置へ戻さない。
- 共有不可の通知はPC・モバイル双方に出し、READYや報告用の時計停止より前に分岐する。

[開発フローと実行記録](../development/ASTRA-SOL-DEVELOPMENT.md)を参照。これは設計確認であり、実装・実画面検証の完了ではない。

## 12. 確定境界・復帰の詳細

- 未確定の再生・描画失敗は当該手の開始状態へ戻す。取消時には助言と推薦ゴーストも復元する。
- 最終盤面・得点・GTR値・ツモ・履歴・終局状態・次手保存点の確定には表示処理を挟まない。
  **データ確定後**の表示失敗は確定済み手を巻き戻さず、再供給・二重加点をせず表示復旧または停止する。
  スコアアタックのグローバル乱数を巻き戻す仕組みは追加しない。
- 非表示中のkeyup欠落で入力が止まり続けないよう、blur／非表示で物理キー記録とPhaserキーを整理する。
  再生の時間進行と操作の解除待ちを分離し、古いEscも次の状態へ持ち越さない。
- 共有不可の案内は完了・取消・リセットで消す。設定操作が再生後に可能であることも短く案内する。
- 自動テストの成功と実画面の確認を区別する。未確認の操作を完了扱いにしない。

## 13. 連鎖中ポーズの入力契約

同一描画フレーム内にkeydownとkeyupが届いても、操作可能な連鎖中のPは1回だけ受理する。
連鎖中Pのみ既存Phaser Keyのdownイベントで即時切り替え、同じ入力をupdateで二重処理しない。
通常プレイの入力方式、スコアアタックの操作、物理キー追跡用window captureは拡張しない。

- 有効な連鎖あり、未破棄、キーボード有効、表示中、解除待ち外の場合だけ受理する。
- 報告／再現検査／結果画面、IME変換中、編集欄にフォーカス中、Ctrl/Meta/Alt付き、repeatは受理しない。
- 拒否した入力は予約しない。解除待ち終了後に新しく押したPだけを受理する。
- userとhiddenの停止理由は独立させる。ポーズ再開が非表示停止を解除しない。
- 登録した自身のハンドラーをシーン終了・破棄で解除する。取消後・破棄後には操作しない。
- 各再生phaseのkeydown→keyup→update、押しっぱなし、拒否条件、登録と解除を検査する。
  再生器のpauseを直接呼ぶテストだけでキー入力を検証済みにしない。

報告画面の文字入力へPが入ることは正常であり、ゲーム入力を有効にするための強制blurやIME無効化は行わない。
