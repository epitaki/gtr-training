# 007 初手解析と色役割の一元化

2026-10-04。Habitica `44bd97c5-213a-4afc-9a1a-d0fdd4f3c316`、P0、全工程GPT-6.1-sol。

## 現状と変更方針

推薦の `createTrainingPlan` は最多色をB、次に出現した色をAとする。
旧GuideManagerは別に個数順でAを選んでいたため、同じ記号の意味が一致していない。
現行の完成見本はtrainingPlanを使うが、旧教材の色Mapも含めて一元化する。

`advisor/OpeningAnalysis.ts` に純粋な初手解析を置く。4個の出現順・色の個数・初出順・型・折り返しの役割を返す。
同率なら実際の初出順で比較する。A/Bは教材図の標準コアと推薦のtrainingPlanで共用する。
PlacementAdvisorの既存公開APIは新解析へ委譲し、GuideManagerも同解析または保存されたtrainingPlanを使う。
再現データに保存された役割を現在の再解析で上書きしない。

AAAAは別色未供給の明示分岐とする。通常供給では除外済みだが、再現・測定の入力として拒否しない。
既存の保存・推薦との互換性のためtrainingPlanの仮色は維持し、教材では別色待ちと説明して仮色を供給済みと扱わない。
初手だけで以後の手順を一意にせず、3手目以降の候補集合・非発火ガイド・完成優先・供給乱数を維持する。

## 受入条件

4色の全256入力、両ペアの4方向、色置換と軸/子の交換を表形式で確認する。
GuideManagerのA/BとtrainingPlanが一致し、保存役割も保護される。
変更前のtrainingPlanを独立した基準計算で照合し、全入力で一致させる。これは品質改善率の測定ではなく構成整理の互換性検証。
AAAAの教材は明示的な別色待ち。後続の複数候補と安全な配置を代表局面で確認する。
アプリ・CLI・サーバー型検査、全テスト、buildを確認する。
