## 目的と保護対象

画像の「オフィシャル」「おすすめ」を切り替え、個別変更・保存・初期化を可能にする。
物理キーを変えても、画面ボタンの「戻す」「評価」が別操作にならない設計とする。
両モードにポーズとクイックドロップを提供する。推薦・採点・乱数・ツモ供給・回転物理・再現形式は変更しない。
8bitテーマ刷新、多重の推薦変更は別タスクで行う。

## 開始時のコードで確認した移行点

- `GuidedPracticeScene.ts` と `PuyoGame.ts` は個別にキーを登録・処理している。ガイドの連鎖中Pと両モードの結果画面には別の入力経路もある。
- `components/game/GameControls.tsx` は固定の合成KeyboardEventを送信する。割当だけ変えるとモバイルの評価が落下に変わるなどの誤動作が起きる。
- `GameManager.ts` に外部画面による停止と復帰時の入力解除待ちがある。設定画面も既存の停止管理へ統合する。
- スコアアタックにはガイド同等のユーザーポーズがないため、今回の明示的な追加機能とする。
- 両Sceneの `landCurrentPair()` に既存の着地・連鎖・履歴・ツモ供給経路がある。クイックドロップから同じ経路を使う。

## 責務

新規ライブラリを追加せず、小規模な `src/game/input/` に整理する案とする。

| 所有先（追加予定） | 責務 |
|---|---|
| `bindings.ts` | アクション型、プリセット、キー正規化、重複検証、表示名 |
| `InputController.ts` | UIに依存しない押下集合・押下エッジ・反復・状態別許可・解除待ち |
| `settings.ts` | 版付き保存、購読、読み書き失敗時の扱い |
| `PhaserInputAdapter.ts` | DOMイベントとScene更新／終了を接続 |
| `components/settings/KeySettings.tsx` | 下書き編集、プリセット選択、個別割当、保存・取消・初期化 |

Sceneは意味のあるアクションを受け、既存のゲーム処理を呼ぶ。古い直接キー処理を残して二重に処理しない。
純粋な入力処理に盤面・推薦を渡さず、core/gtr/advisor/guide/feedbackからinputへ依存させない。
実装時に構成文書と依存方向の検査も更新する。

基本アクションは移動左右・回転左右・高速落下・クイックドロップ・ポーズ。
アプリ固有アクションは巻戻し・評価・ガイド・自由落下・共有・終了。
結果の新ゲーム／退出、メニューの決定／戻るは状態専用とし、プレイ用割当から分離する。

画面ボタンはGameManager経由の `pressAction/releaseAction` 相当の意味アクション送信へ移行する。
pointer IDなど入力元別に保持し、一方の指や物理キーを離しても他方の保持を消さない。
キャンセル・フォーカス喪失・破棄時は解除する。物理キーの合成イベントを設定変更に追随させる方式は採らない。

## 割当・編集・保存の案

- 初期値は利用者承認済みの「おすすめ」。両プリセットと個別変更を提供する。
- 固有操作の仮既定値は巻戻しU・評価E・ガイドG・自由落下F・共有R。終了はポーズ画面の明示ボタンとする。
- Esc/F1はプレイ／連鎖中のポーズ。結果のEsc退出は維持する。Pを互換割当として残す場合は、画像由来ではない追加として明示する。
- `KeyboardEvent.code` で保存する。Num4/6はNumpad4/6としてNumLockで意味を変えない。
- Ctrl/Shiftは左右共通の表示割当とし、内部の押下状態は左右を別に保持する。
- 複数キーを許可し、同時に有効な別アクションとの重複は操作名付きで拒否する。
- プリセットは基本7操作だけを置換する案とし、固有操作との競合があれば保存前に解決する。「すべて初期化」は別操作にする。
- 下書きを「保存」で一括適用し、「取消」は無変更。適用で盤面を再生成しない。
- `version: 1` と全割当を専用保存領域へ保存する。報告・再現データの版や保存キーは変更しない。
- 不正JSON・未知版・不正キー・重複は既定値へ復帰して通知する。読取り時点で破損原文を上書きしない。
- 書込み失敗は「今回のみ適用・保存できなかった」と表示する。適用前後の保留入力と反復を捨て、解除後の新しい押下を要求する。

## 状態と入力の安全性

| 状態 | 扱う操作 |
|---|---|
| 通常 | 基本操作とモードで利用可能な固有操作 |
| ポーズ | 再開、設定、終了。盤面操作なし |
| 連鎖再生 | ポーズ、ガイドの取消／巻戻し。評価等の利用不可案内と共有拒否は現行を維持 |
| 結果 | 明示的な新ゲーム／退出、ガイド共有。Space／Escはこの状態だけの操作 |
| ゲームオーバー・表示障害 | 現行の復旧／巻戻し／退出を維持 |
| 設定・報告・一覧・再現検査 | ゲーム入力停止。再現検査からの再開条件も維持 |

移動・高速落下のみ反復し、初回即時、反復間隔は現行150msを仮維持する。OSのkeydown repeatには依存しない。
回転・クイックドロップ・評価・ポーズは押下エッジ一回。逆方向の同時押しは相殺する案とする。
移動の待ち時間でポーズや回転を遮断しない。

状態を変える操作を処理したフレームでは、残りの盤面操作と自然落下を実行しない。
切替時の保留押下を捨てる。blurでkeyupが届かない場合は押下集合を解除し、復帰時のrepeatを新規押下とみなさない。
IME／入力欄／contenteditable／ゲーム外のボタンにフォーカスがある場合は盤面操作を受けない。
ブラウザイベントを一律に抑止せず、ゲームが消費した割当のみを抑止する。2026-09-29補足: ゲーム面focus中の割当済みスクロールキー（矢印／Space、結果specialを含む）は、ゲームactionが拒否される生成待ち／結果／停止等でもブラウザ既定動作を抑止する。action発行の許可とは分離し、拒否時は入力状態を変更しない。ゲーム外focus／編集／IME／既存shortcut除外は維持。[修正設計と検証](../records/ARROW-SCROLL-FIX-20260929.md)。

Ctrl単独がゲーム操作の場合、Ctrl+Cの開始時点でCtrl操作が先に発生し得る。
ゲーム面にフォーカスがあるときだけ扱い、Ctrl/Meta修飾付き文字を別のゲーム操作に解釈しない。
「ブラウザショートカットと完全無競合」とは保証しない。キー取得は明示的な取消ボタンを備え、Esc自体の割当も取得可能にする。

## クイックドロップ

現在位置・向きの組を既存 `PuyoPairManager.canMove/movePair` で支持位置まで下げ、`landCurrentPair()` を一回呼ぶ。
出現位置や推薦位置から再計算しない。接地済みでも確定でき、自然落下OFFでも実行できる。
ちぎり・連鎖・履歴確定・ツモ乱数は既存経路に任せる。連鎖中／結果中は受けず、保持で次ツモまで連続落下させない。

高速落下は既存の一マス移動と自然落下側の着地確定を維持する案とする。
自然落下OFF時の接地確定にはクイックドロップを使う。落下・供給規則の別の変更を同時に混ぜない。
