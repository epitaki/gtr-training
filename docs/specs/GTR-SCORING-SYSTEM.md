# GTR評価システム設計書

## 概要
GTRパターンの評価をロジックベースで実装したシステムです。note.mdの仕様に基づいて実装されています。

更新日：2026-09-27。採点版 `masked-foundation-minimal-v2` を実装。
右端位置だけの加点を廃止し、最小の土台5連鎖の完成を評価する。設計と検証は
[土台の完成点と伸ばしの分離](../design/GTR-SURFACE-QUALITY-20260927.md)を参照。
余り「なし ＞ 1個 ＝ 同色連結」と、範囲内だけを採点する原則は維持する。
100点到達率・土台内5連鎖到達率の保存結果向け集計を追加した（[実装記録](../records/ADVISOR-FOUNDATION-PREPARATION-20260924.md)）。
範囲外の相方・上部の伸ばしは土台点から分離済み。全盤面の接続見込み・危険は別表示する。
実装・検証・残件の一覧は[最新の進捗](../progress-report.md)を参照。

> [!IMPORTANT]
> これは既存の結果画面用スコアの設計記録です。ここでの「GTR」は左折りの標準GTRコアを指し、形の得点は実戦での強さや唯一の正解を意味しません。逐手の候補提示を行う `PlacementAdvisor` とは目的が異なります。

## 品質評価との区別（2026-09-19追補）

ガイドの品質は、完成率・連鎖数に加え、**人間らしい構築手順を主要な評価軸**として判定します。
基準は[品質・人間らしい手順の評価基準](GTR-QUALITY-CRITERIA.md)を参照してください。

右端への配置や同色の積み上げを、それだけで良い推薦・有効な発火点伸ばしと評価する根拠にはしません。
2026-09-27に「右上にあると加点」を廃止し、最小完成へ置き換える。平坦さにも固定加点しない。
品質方針の策定と画面得点の変更は別に扱い、得点の増加を推薦成功率の改善とは呼びません。

## 100点満点への補正（2026-09-24）

利用者の画像の3つの理想形は、いずれも下3段＋右端4段目の1個から5連鎖・全消しになる。
以前は折り返し100点と連鎖尾85点をそのまま平均し、92.5を丸めた93点だった。
現在は各項目をその満点で正規化してから同じ重みで平均し、**3形とも100点**とする。
色を入れ替えても同じ。形の順位・名前・特定の配色に満点を直接割り当てる処理ではない。

また、1・2列目の4段目に何かあるだけで折り返し120点を与えていた旧ボーナスを削除した。
折り返しは上への積み上げで増点せず、総合スコアは0〜100点に制限する。
連鎖加点は従来どおり5連鎖まで。下記の評価範囲修正以降、土台の連鎖数と全盤面の実連鎖は区別する。
連鎖尾の詳細値 `chainTailScore` は互換性のため素点（現設定で最大85）を維持する。

### 満点に必要な条件

旧条件は全盤面19個だったため、空盤面から発火せず2個ずつ積むガイドでは満点に到達できなかった。
2026-09-25に、個数と配置の満点条件も**範囲外を除いた土台**へ統一した。
相方1個だけを特別に削除する処理ではない。範囲外の上積みが増えても土台点は変えず、
範囲内の邪魔なぷよを都合よく除くことはしない。

2026-09-27の見直しでは、100点は次のすべてを満たす盤面に限る。

- 13行×6列で、範囲を切り出した土台が安定し、仮想発火前の消去がない。
- 標準GTRコアがあり、その元セルが先頭2段の正しい順で消え、仮想発火でちょうど5連鎖。
- 仮想発火後に評価用土台が空になる。
- 発火前の評価範囲内のぷよは最小の19個。仮想発火の1個を加えると、5回×4個の20個。
- 4段目の列位置に追加制限を付けない。評価範囲そのものは従来どおり。

条件を満たさない盤面は正規化した部分点を最大99点に制限する。
例えば画像左の理想形に2列目4段目の黄色を追加しても、その位置は範囲外なので土台100点。
3〜5列目4段目は範囲内なので、19個の土台へ余分な1個を追加する場合は100点にならない。
一方、19個の構成要素として5列目4段目などを使う形は減点しない。Y字3・Y字8も満点対象。
余りがある・右端だけを高く積んだ・6連鎖以上になったことでは満点にならない。
この満点条件は土台の練習目標であり、実戦上の唯一の正解ではない。

### 基本形2連鎖と全盤面の状態表示

結果画面は「土台スコア」と明記する。基本形の元セルが1段目・2段目の順に消えた場合だけ、
「土台5連鎖 = 基本形2連鎖 + 連鎖尾3連鎖」のように内訳を表示する。
形の一致に無条件で2を足さない。同時消しで1連鎖になる例は2連鎖扱いしない。

範囲外個数と全盤面の本線接続見込みは別表示。共通の物理シミュレーターと既存の有界接続探索を使う。
出現位置の閉塞・消去前の不安定盤面は注意表示し、接続が見つからない場合は「未確認」とする。
仮置き1〜2個による見込みを、実際に発火済み・全上部が有効活用済みとは表示しない。
土台100点でも発火口が塞がる場合があるため、土台点を推薦の安全判定の代わりにしない。
2026-10-04に両結果画面の完成題名を共通化した。標準コア・土台5連鎖・現在ペアでの本線発火可能と将来色待ちを分ける。発火可能は実発火済みではない。
実在セルをコア・土台参加・土台余り・範囲外の接続見込み/未確認へ分類して個数を表示する。用途は有限の仮想本線における関係で、未知のツモに対する最適用途や伸ばしやすさは未判定。[設計と受入](../reviews/GTR-ANALYSIS-CHECK-20261004.md)。

右側の段差を残す狙いは雪崩への伸ばしやすさだが、6列目が常に最高である必要はない。
平らな足場も折り返しから右へ伸ばす際に使える。高さだけで色や消去順の接続を保証せず、
[再調査と教材の限定接続例](../design/GTR-SURFACE-QUALITY-20260927.md)で分けて説明する。
この採点変更では結果採点と教材説明だけを変更した。
後続の[ガイド改善](../records/ADVISOR-FOUNDATION-SHAPES-20260927.md)で右端限定の候補と追加優遇を見直すが、
採点版と評価範囲は変えない。推薦の改善実績は採点定義変更による再分類と分けて記録する。

## 評価システムの構成

### 非発火ガイドの尾完成と土台点の違い（2026-09-26）

ガイドの尾完成は `GuidedTail.ts` で判定する。既存の完成判定に加え、尾の必要セルが実在し、
評価範囲内で3連鎖以上が成立し、その元セルの消去順へ戻る全盤面接続またはキー待ち仕込みを
検証できた場合も完成として表示・集計する。キー未配置を、今発火できる・実際に消したとは扱わない。
これは尾完成の見落とし補正であり、土台の連鎖数・余り・満点条件の変更ではない。

利用者報告を改善した横3では、3列目4段目の青が採点範囲に入るため、当時の土台点は93点だった。
同じ研究JSONの局面は現行の `masked-foundation-minimal-v2` では90点。余り1個・尾68/85とコア100/100の等重みで計算し、過去の93点を現在の採点結果へ読み替えない。
土台5を守り余る青を回収する有効な手順でも、範囲内の青を除外したり、頭の連鎖を加点したりしない。
同じ判定での500件比較と旧フラグとの差は[完成前のキー待ち構築](../records/ADVISOR-HEAD-CONSTRUCTION-20260926.md)に記録する。

### 1. 評価範囲

#### note.mdに基づく評価範囲
```
1 2 3 4 5 6
_ _ / / / /  ← 10行目：3-6列目のみ評価
/ / / / / /  ← 11行目：全列評価
/ / / / / /  ← 12行目：全列評価
/ / / / / /  ← 13行目：全列評価（最下段）
```

- 1-2列目: 11-13行目
- 3-6列目: 10-13行目

### 評価範囲外の連鎖参加を除外（2026-09-24 フィードバック修正）

評価用コピーを作る時点で、範囲外のぷよをすべて除く。その後、(1,10)へ仮想発火ぷよを1個置き、
共通シミュレーターで消去・重力を解決する。仮想発火ぷよは土台に含まれない唯一の補助ぷよ。
範囲外からの落下、同色の合流、上の発火点伸ばし、余りへの混入は採点に利用しない。
範囲外の発火口の上積みも土台の連鎖を変えない。実際に発火可能かどうかは別の物理判定で扱う。

利用者の13手目の盤面は、全盤面なら5連鎖だが、範囲外の青が4連鎖目、赤が5連鎖目に参加していた。
修正後の土台評価は **3連鎖・余り8個・71点**（修正前は5連鎖・余り3個・85点）。
実プレイで起きる5連鎖と発火後の残数は変更しない。推薦候補の「即時連鎖」は全盤面の実消去なので、
土台の評価連鎖数と一致するとは限らない。

`EvaluationRange.ts` の範囲定義を採点と結果画面のハイライトで共有する。
採点は `GTRDetector.detectGTR`、推薦の物理判定は `getFullBoardChainCount` と
`MainFireAnalysis` を使い分ける。旧実測の「5連鎖成功率」は実発火の指標であり、土台内5連鎖率の証拠ではない。

### 5. あまりぷよ評価: 最大20点

#### あまりぷよの定義（note.md仕様）
- 評価範囲内で連鎖に使われなかったぷよ
- 同じ色で連結していることが重要

**評価:**
- あまりぷよなし: 20点（最高評価）
- **複数色のあまりぷよ: 0点**（連結していても評価しない）
- 余り1個: 18点
- 単一色で余りすべてが完全連結: 18点（2個と3個を区別しない）

※ 4連結は消えるため、あまりぷよとして存在しない

2026-09-24の追加指定により、**なし ＞ 1個 ＝ 同色連結**へ変更。

過去文書の点数は当時の採点値であり、新しい点数へ読み替えない。

## 総合スコア計算

### 計算式
```
連鎖尾の素点 = 連鎖数ボーナス + 最小完成ボーナス + あまりぷよ評価
連鎖尾の満点 = 5 × 10 + 15 + 20 = 85
部分点 = 四捨五入(100 × ((基本形スコア / 100) × 0.5 + (連鎖尾の素点 / 85) × 0.5))
総合スコア = 満点条件をすべて満たすなら100、それ以外はmin(99, 部分点)
総合スコアの範囲 = 0〜100点（折り返しがなければ0点）
```

実装は満点・重みを設定から取得し、重みの合計で割って正規化する。上の式は現行設定の場合。

- 5連鎖以上: 「素晴らしい！{chain}連鎖のGTR！」
- 4連鎖: 「良いGTR！{chain}連鎖達成」

## メリット

1. **透明性**: プレイヤーが評価基準を理解しやすい
2. **調整可能**: configファイルを変更するだけでバランス調整が可能
3. **拡張性**: 新しい評価軸を簡単に追加できる
4. **学習効果**: どこを改善すべきか明確
5. **実装効率**: 400種類を定義するより遥かに少ない工数

## デメリットと対策

| デメリット | 対策 |
|------------|------|
| 特殊パターンの評価が難しい | 固定の形ボーナスではなく、発火後の消え方・接続・残存ぷよを検証する |
| 完璧な評価は困難 | ユーザーフィードバックで継続改善 |
| 初期調整が必要 | プレイテストで係数を調整 |

## まとめ

note.mdの仕様に基づいたロジックベースの評価システムを実装しました。

### 主な特徴
- **評価範囲**: 1-2列目は11-13行目、3-6列目は10-13行目
- **必須折り返し**: なければ0点
- **連鎖数**: 評価範囲内だけで検出し、スコア加点は最大5連鎖
- **あまりぷよ**: 同色連結で高評価、複数色で0点
- **設定分離**: 点数チューニングが容易

これにより、プレイヤーが左折り標準GTRコアと、この画面で評価する連鎖尾の条件を確認しやすくなりました。
