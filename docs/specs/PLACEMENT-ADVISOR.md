# PlacementAdvisor 配置推薦システム設計書

## 概要

`PlacementAdvisor` はフィールドの現在の状態と手駒（ぷよペア）を入力として、
GTR完成に向けた配置候補を比較・推薦するシステムである。探索範囲内の近似評価であり、唯一の最適手を保証しない。

## 現行ガイドの入口（2026-09-24：完成後も構築を継続）

利用者の指定により、画面のガイドは `ContinuousAdvisor` を入口にする。
従来の `PlacementAdvisor` は土台構築の候補生成と、過去の実発火ベンチマーク用に残す。
以下の従来仕様にある「打てる本線の発火優先」は、その旧エンジンの仕様であり現行ガイドの最終選択ではない。

- ガイドは即時消去・出現位置閉塞になる配置を推薦しない。手動の移動・回転・発火は変更しない。
- 土台内5連鎖と標準コアの成立までは既存の構築候補から消去する候補を除く。
  現在手で実際の土台5が完成し全盤面の接続も保つ候補を、旧方式の将来発火順位より優先する。
  折り返し完成後は、最大3組で100点土台まで実配置できる経路を追加確認する。
  現在手で土台5が完成できる場合は、その候補の中からのみ満点経路を優先する。
  終端の土台100点と全盤面の接続見込み・尾完成を別に確認し、経路がなければ既存順位に戻す。
  仮置き発火でも全盤面に6個以上残る場合は満点経路を優先しない。この条件は実発火後平均余りの測定とは別。
  2026-09-27：満点候補を右端4段目の形に限定せず、5列目を使うY字8やY字3の完成経路も調べる。
  同じ初手では最短完成手数の全成功経路を比較し、完成手数→全盤面の余り→累積ちぎり→
  既存の高積み・谷コスト→最大高さ→3〜6列の最大段差→段差合計の順に選ぶ。
  完全同等なら元の推薦順位を保持する。平坦さのために完成・回収を見送らない。
- 現在手の完成・満点経路がない場合は、配置後の土台が完全に同じ候補間で相方の回収を比較する。
  本線の消去順・仮発火の必要数・本体の早消しリスクを守り、選択中の完成骨格も維持できる場合だけ置き換える。
  発火口を空けること自体を罰せず、頭・尾へ接続できる根拠のある配分を選ぶ。
  [完成前の相方配分と比較結果](../records/ADVISOR-SPARE-ALLOCATION-20260925.md)を参照。
- 2026-09-26：同じ土台を進められる相方配分に限り、左の横2個からキー待ちの頭を始める。
  土台骨格を仮完成した際の消去順を検証し、開始後は横3・左右L字の未完成キー待ちも探索対象にする。
  仮完成は実績ではなく適合条件。土台5を現在手で完成させる配置では、すでに仕込んだ頭の回収・必要数が
  同等なら低さとちぎりを比較する。土台100点を保つためだけの縦積みへ固定しない。
  [適用範囲・実供給での検証](../records/ADVISOR-HEAD-CONSTRUCTION-20260926.md)を参照。
- 成立後は、見えるCURRENT/NEXT/NEXT2のみを最大3手・各段24ノードで探索する。
  土台5連鎖を保ち、元の土台の消去元セルと順序を保つ発火点・連鎖尾の接続を比較する。
- 各列の上へ同色1〜2個を仮置きし、動いた発火口も確認する。必要な色がまだ供給されていない仕込みであり、
  到達済み連鎖・100点・実発火成功には数えない。任意の多重や3個以上不足する発火口は網羅しない。
- 雪崩・鶴亀は別グループでも、直前の本線消去による落下からつながる場合は認める。
  無関係な同時消去は認めない。連鎖数だけでなく残り個数、追加必要数、谷・高さ・ちぎりも比較する。
- 安全な接続を確認できる候補がなければゴーストを消して確認を促す。消去を代わりに推薦しない。
  先読みは有界であり、今後ずっと積み続けられる保証ではない。
- 土台100点への到達後も、点数を固定するために上積みを左右へ追い出さない。
  土台5の維持と全盤面の接続・回収を優先する従来の伸ばしを使う。伸ばしにより土台の点数が下がる場合もある。

上の伸ばしは全盤面の接続として扱い、評価画面の土台の連鎖数へ混ぜない。
完成状態は盤面から再判定し、巻き戻し・リプレイで古い完成フラグを持ち越さない。

## 品質方針と実装仕様の区別

2026-09-27採用版：指定動画の「近い派生を残す」考え方を、完成前の完全同点候補の比較へ追加。
CURRENTを置いた直後の完成候補について、列ごとの次に必要な色が同じなら一つの受け方として数える。
基本形完成後・尾未完成に限定し、安全性・既存スコア・余剰回収が同点、さらに現在手の進捗・余剰数・尾型が一致する候補間だけで使う。
発火経路や完成準備など別評価で選ぶ候補は除外する。骨格生成、探索の数値スコア、ビーム幅、採点、供給は変えない。
旧優先条件で安定整列した完全同点ブロック内を、現在手の尾型・進捗・余剰数・土台／尾完成状態で分け、
同じ組の元の位置へ受け方件数の降順で安定して戻す。対象外／情報なしの位置は動かさない。
固定500ゲームで土台5連鎖379→380、尾480・基本形496・100点6を維持。全1034テスト、独立Sol3人×3ラウンドとAstra確認を完了。
既知集合の1件増であり、ちぎり・高い谷は微増したため人間らしさ全般の改善とは扱わない。
完成候補の総数や動画の派生件数を勝率と扱わない。[設計・観測範囲・比較記録](../records/GTR-COMPLETION-VIDEO-20260927.md)を参照。

右の完成見本はguideの教材モデルであり、推薦から参照しない。推薦が返す型／色は採用した探索経路に対応させ、
別経路へ差し替わって型を特定できない場合は未指定とする。教材表示の選択は推薦・盤面・履歴・供給を変えない。

GTR完成を第一目的とし、人間が再現しやすい自然な構築手順も主要な評価軸とする。
採否の基準は[品質・人間らしい手順の評価基準](GTR-QUALITY-CRITERIA.md)に集約する。
以下の内部スコアはそのための現行手段であり、高得点であること自体を自然さの証明にしない。

初手の折り返し優先、Y字の組み始め優先、自由形でのちぎり抑制は実装済み。
発火点伸ばしは[調査・盤面検証](../research/GTR-HEAD-EXTENSION-RESEARCH.md)に加え、2026-09-22の作業版で
左端に支持色と落下キーを積む限定形の仕込み・本線認定を実装した。一般的な多重は未対応。
最初の形別調整は完成率を下げたが、骨格の選択肢と完成評価を見直した。
[後続の改善・比較](../records/ADVISOR-CONSTRUCTION-20260922.md)に現行の変更と残る品質上のトレードオフを記録する。
結果画面の形状得点・候補の内部スコア・改善版の品質評価は区別する。

## アーキテクチャ

トレーニング計画がある場合、まず5連鎖骨格探索を行う。Y字・L字・座布団を含む
各19個のぷよからなる初期11種類と、下3段＋4段目1個の41種類の骨格について4色の配色を列挙し、共通シミュレーターで「配置時は消えず、
標準発火点に1個加えると5連鎖する」配色だけを採用する。
CURRENT/NEXT/NEXT2の最大3組、幅32のビーム探索で、骨格全体の進捗と不足色、
余剰ぷよ、高さを比較する。余剰ぷよは完成予定の骨格と一緒に発火検証し、
後続の落下を壊す配置を避ける。5連鎖の実発火は終端として扱い、先送りしない。
初期11種類は元の3配置に右端が3段になる8配置を加えたもの。最初の2手ではその11種類だけを使う。
低い41種類も動画からの転記ではなく、配色ごとに物理検証する候補である。
各探索段では、同じ盤面への到達を重複排除した後、初手候補ごとに最良の継続を1つ残し、残りを得点順に埋める。
これによりNEXT2を見る前に1種類の有望形だけで探索枠が埋まることを抑える。幅32・先読み3組は変えない。

列途中にある下側の有効ぷよを、固定配色の不一致だけで除外しない限定拡張も行う。
3〜6列の下3段以内かつ尾・支持の上で、現在の4連鎖目以降に参加する1個を骨格へ挿入できる。
元の骨格ぷよが全て同じ段階で消え、追加セルも回収できる5連鎖をシミュレーターで検証する。
挿入は1個まで。元の19個の進捗点を増やさず、回収される余剰として扱う。
現在手の低い回収に限り8点を加え、挿入候補にはちぎりコストも付ける。実発火の終端優先は変えない。
これは全体の高さを一律に下げる規則ではない。[青緑報告と検証範囲](../records/ADVISOR-LOWER-TAIL-20260922.md)を参照。

現在の配置が高い塔や1列幅の深い谷を作る場合は、骨格探索・自由形の両経路で表面形状を減点する。
下4段以内の骨格を対象外とし、2段までの段差を許容する。左端の発火口を埋める誘因は作らない。
減点上限は90で、骨格の1セル進捗100より小さくする。骨格候補の成立性・発火口・色順の制約は変えない。
探索では現在手の減点を先読み後も保持し、微小な将来得点差による高積みを抑える。
まだ置いていない先読み先の形状を追加減点して、現在のY字や低い接続を避けさせることはしない。
CURRENT自体の本線5連鎖の実発火は減点しない。
NEXT/NEXT2での実発火候補は、早い発火→独立巻込みなし→土台内5連鎖成立の順で比較する。
最後の土台判定は実在する発火直前の確定盤面を範囲内だけで評価するもので、仮完成図は使わない。
同じ成立クラス内ではCURRENTの形状を「危険帯なし→あり」の順で比較する。
危険帯内は形状コスト→実残数、危険帯外は実残数→形状コストの順。
高い谷は内側列が両隣より3段以上低く、両隣が5段以上の状態。
先読み発火用の減点は「谷あり45点＋通常形状コストの半分」、谷なしでは後半のみとする。
上限90のため、早い発火の差500・副次消去の差100を逆転しない。先読み先の盤面の形状は加算しない。
危険帯の境界は45点で、高い谷だけでなく通常形状コストが上限に達した塔も含む。
内部スコアの大小だけではなく上記の比較順が推薦を決める。土台5を優先することによる高さの悪化も
[今回の比較記録](../records/ADVISOR-FOUNDATION70-20260924.md)で別に確認する。
基本評価は[平坦さの改善記録](../records/ADVISOR-SURFACE-20260922.md)、終端でCURRENTの差が消える問題への対応は
[009-Dの1,500ゲーム比較・悪化例](../records/ADVISOR-TALL-WELLS-20260922.md)を参照。

折り返し7セルが完成し、接続済みの教材尾がまだ完成していない間は、
CURRENTの軸・子が同じ成立可能な骨格に使えるかを補助評価する。
`PairPlacementUse`で骨格セル・検証済みの下側接続・限定頭のセル・用途未確定を区別し、
用途未確定を1個8点、最大16点減点する。用途未確定は永久に捨てぷよという断定ではない。
非消去の先読みでは元のCURRENTの着地点を保持し、その時点の選択骨格に対して用途を再確認する。
別々の骨格の役割を合算せず、単なる同色隣接や仮完成での余剰消去を確実な用途とは数えない。
初手・折り返し未完成では適用しない。尾や骨格の完成、実発火でも減点を止める。
Y/座布団/Lの構築コストと、本線5連鎖の発火優先は変更しない。
既知1,000ゲームと未使用500ゲームで完成数を維持したが、補助指標の改善は小幅で混在する。
[試行・採否・回帰例](../records/ADVISOR-PAIR-USE-20260922.md)を参照。

折り返し7セルが呼び出し時点で完成している場合、5連鎖骨格の不足色を列ごとに下から比較する。
`CompletionWait`は4色等確率の単色供給と理想的な配置を仮定し、完成までの期待供給数を計算する。
使えない色は待ち、使える色はその色を先頭に持つ列のうち残り期待値が最小の列へ1個だけ置く。
「期待供給数−必要セル数」の4倍を最大80点まで減点し、有効セル1個の100点より小さくする。実際の必要組数ではない。
同じ物理成立可能な骨格の中で計算し、完成した骨格と実発火は減点しない。
最後の発火色・頭の追加セル・未知の将来ツモは計算に含めず、実際の着地と相方の影響は既存の3組探索で扱う。
受け口を残すこと自体への加点はしない。[初期の採否記録](../records/ADVISOR-TAIL-WAIT-20260922.md)と
[土台5への後続調整](../records/ADVISOR-FOUNDATION70-20260924.md)を区別する。

教材尾が既に完成している場合は、固定骨格以外にも既知3組の合法な非消去配置・実発火を探索する。
準備点を比較するのは、見えている組を全て置いた終端のみ。仮の発火色を実発火には数えない。
同じ準備区分内で全盤面の仮発火後の残数を1個100点減点し、発火ツモの相方4色を全て受けられる
土台内5連鎖には2000点を付ける。未達3→4リンクだけの加点はしない。
右上段差への追加100点は、9/27の結果採点変更の時点では残していたが、
後続の[ガイド改善](../records/ADVISOR-FOUNDATION-SHAPES-20260927.md)で廃止した。低さへの別の固定加点には置き換えない。
満点探索の右端限定も外したが、全満点形の網羅や未知ツモへの伸ばしやすさを保証するものではない。
残り2個以内で、仮完成時も土台5・4色の相方受入が成立する型は、上部依存の準備へ安易に替えない。
ただし仮完成後の余りが5個を超え、既知3組にその型の先頭不足色がなければ保護を解除する。
これらは条件付き構築判断であり、未供給の色を実際に置いた扱いにはしない。CURRENTの実発火は常に先に比較する。

2026-09-20の1,000ゲーム比較では、元の進捗・余剰個数・高さの点数を保ったまま、
**同点の探索状態に限り、完成した骨格と一緒に回収される余剰ぷよが多い方を選ぶ**第二比較を追加した。
現在または見えている3組以内で完成した骨格が対象で、未完成骨格を仮に埋めただけの回収数は優先しない。
落下前の位置と消去時の同色連結を追い、独立した別消しを回収として数えない。
ビーム探索の同点順と、最終推薦の同点順に適用し、実発火の終端優先度は変更しない。
これは発火点の移動や多重折りの実装ではない。余り削減と、ちぎりの小幅増を含む
[前後比較・代表局面](../records/ADVISOR-NATURAL-1000-20260919.md)を参照。

2026-09-24には、同色の本線へ直接合流する余剰に加えて、本線の支持消去から落下して消える
4〜6列の余剰を追跡する限定評価を追加した。元の5連鎖の各ぷよが元の消去段を維持することを前提とし、
直前の本線につながる消去で落下した連結だけを対象にする。独立した別消しや単なる高積みは対象外。
基本雪崩の1・1・2配置とその他の鶴亀型の落下回収を区別して検証するが、形名による倍率は付けない。
呼び出し時点で教材尾が完成し、現在または見えている3組の探索盤面で5連鎖骨格全体が完成している場合だけ、
回収セル1個8点、最大16点を加える。未完成骨格を仮に埋めた回収には加点しない。
本線5連鎖の実発火は引き続き終端で優先する。既存の頭伸ばし評価は維持し、この追加加点を頭の仕込みに重ねない。
`PlacementAdvisor.getAdvice`を通じて実際の配置ガイドへ反映する。専用コーチ文や結果画面の100点条件は変更しない。
[実装・比較・限界](../records/ADVISOR-TAIL-CASCADE-20260924.md)を参照。

2026-09-22の現行作業版では、構築途中の骨格からY=0、座布団=80、L=90の構築コストを引く。
以前の「座布団だけ150減点、Yだけ1加点」はL字を座布団より有利にしていたため変更した。
これは利用者の練習方針であり、L字が普遍的に弱いという断定ではない。
有効セル1個の進捗100未満に抑える。150／190の試行では形の好みが1個分の有効進捗を上回っていた。
折り返しと連鎖尾が実際につながった中間目標には100点を与える。必要な色付きセルがすべて存在し、
実シミュレーションで3連鎖以上の本線へ接続することを確認する。頭の仕込み不足を仮の実発火へ数えない。
色・配置が適合し、実連鎖の検証を通る骨格だけが対象。骨格が完成した場合は従来の完成点1000を使い、
これらの形別調整は行わない。完成間近の座布団や、見えているツモでの確定5連鎖を壊して
Y字へ作り直す規則ではない。[再現と測定記録](../records/GTR-Y-TAIL-PREFERENCE.md)を参照。

発火点伸ばしは、標準コアを保ち、1列目に支持色C／発火色Aを下から積み、2列目のCへ接続する形に限定する。
不足するCを仮に補ったとき、最初の消去が頭だけで起こり、その後の各段で元の本線ぷよがすべて消えることを検証する。
仮補充を実ツモ・実発火とは扱わない。あと2個必要ならGTR発火可能判定を付けず、不足色と個数を表示する。
あと1個なら移動先の発火口で検証でき、実際の組ぷよが接続を完成させた場合のみ本線発火へ計上する。
尾の形が完成済みであることと、頭がまだ仕込み段階であることも分離する。
左端の落下キーの上は相方2個までに制限し、他の形はこの認定に含めない。

同じ探索段で安全に骨格セルを進められる候補がある場合、新しく頭を始める候補をビーム選別前に除く。
頭の有用性加点は16〜18点で、骨格セルの100点を超えない。完成済み本線の即時発火優先は維持する。
さらに骨格探索では、既に5連鎖が成立した通常発火口を新しい頭待ちで塞ぐ候補を除く。
既に仕込んである頭の継続・発火は対象外。自由形全般や一般的な多重への禁止規則ではない。
低い候補を追加しても依然固定骨格であり、L字の先の任意の伸ばし方や未知ツモの実供給は保証しない。

配置前の盤面が2個以下（通常の空盤面からは最初の2手）では、合法かつ消去・ゲームオーバーを起こさず、
5連鎖骨格と矛盾せずに折り返し7セルの不足を減らせる手を先に候補へ残す。
これはビームを絞る前に、先読み内の各盤面にも適用する。そのような手がなければ
連鎖尾候補を残す。3手目以降は、2個とも折り返しの不足を埋める場合、折り返し＋尾へ同じ型の中で両方使える場合、
または折り返しの最後の不足を埋める場合に、この優先を使う。最後の1色を相方の都合だけで延々と待たない。
初手の同色ペアを、左下の横2に使えるのに右端へ送る問題への対策であり、
すべての右側配置を禁止する規則ではない。[初手の調査・検証](../research/GTR-OPENING-RESEARCH.md)を参照。

3列目最下段が空でどこかが5段以上なら、CURRENTでその接続セルを埋め、
2個とも同じ物理成立可能な骨格・下側接続・検証済み限定頭に使える候補だけを骨格探索に残す。
この条件を満たした同じ候補群をNEXT/NEXT2にも渡し、別骨格の役割を合算しない。
該当する候補がない時や既存盤面が骨格に適合しない時は、以下の汎用スコアリングに戻る。
高さだけで探索を一律に止めず、相方を高い位置へ捨ててまで骨格優先にもしない。
無条件解除の失敗例と限定対応の検証は [009-Cの結果](../records/ADVISOR-LEFT-CONNECTION-20260922.md) を参照。
未確認の将来ツモやseedは
探索へ渡さない。全合法配置の着地・実発火情報はどちらの経路でも共通計算する。
自由形でも、教材の連鎖尾が認定済みかどうかに関係なく、基準本線が5連鎖以上で、現在の組ぷよによる
本線の実発火を確認できた配置には、骨格探索と共通の終端優先度を適用する。
判定は各段で消える元ぷよまで照合し、発火後に出現位置が塞がる配置は対象外。
Y/L/座布団の完成認定自体は変更せず、「形を教える評価」と「成立済みの本線を打つ判断」を分離する。
構築中の骨格探索は従来どおり、先読み上の目標発火に型の完成認定も要求する。
まだ打てない盤面から型のない発火ルートへ誘導する変更ではなく、現在手の打ち逃しだけを防ぐ。
今すぐの通常発火（110000点）を、独立した副次消去付き発火（109900点）、
次のツモでの通常発火（109500点からCURRENTの形状コスト0〜90点を引く）より優先する。発火色がまだ来ていない場合や
5連鎖未満の場合に、この優先度を付けることはない。

骨格の列変換と不足色集計は、一時配列・Mapの生成を抑えて計算する。
中間目標の連鎖検証は色付き接頭部と必要高さを満たした候補に限り、同じ盤面では1回にまとめる。
探索幅、先読み範囲、成功条件は変更しない。
70%達成時の計測・レビューは [改善記録](../records/ADVISOR-GOAL70-REVIEW.md)、
その後の再測定は [完成度改善記録](../records/ADVISOR-QUALITY-20260918.md)、
初手・連鎖尾調整後の保存済み比較は [人間の手順との比較](../research/GTR-HUMAN-PLAY-STUDY.md) を参照。

```
getAdvice(field, currentPair, nextPair?)
  │
  ├─ analyzePhase(grid)             ← フェーズ判定・基準本線の生成
  │
  ├─ 全配置候補を列挙（4回転 × 6列）
  │   │
  │   ├─ ChainSimulator.simulateTurn()
  │   │   ├─ placedGrid             ← 着地直後の仮配置盤面
  │   │   └─ stableGrid / clearSteps← 消去・重力後の盤面と連鎖結果
  │   │
  │   ├─ scoreFoldProgress()        ← ① 折り返し進捗スコア
  │   ├─ scoreChainTail()           ← ② 連鎖尾スコア（パターン構築ガイド）
  │   ├─ scoreConnectivity()        ← ③ 同色連結スコア
  │   ├─ scoreHeightPenalty()       ← ④ 高さペナルティ
  │   ├─ scoreChainSimulation()     ← ⑤ 連鎖シミュレーション
  │   └─ evaluateLookahead()        ← ⑥ NEXT/NEXTNEXT先読み（上位候補のビーム探索）
  │
  │   totalScore = Σ(スコア × フェーズ別重み) + lookaheadScore × DISCOUNT
  │
  └─ スコア降順ソート → bestPlacement を返却
```

## 1. フェーズシステム

ゲームの進行状況に応じて3つのフェーズを自動検出し、各スコアラーの重みを切り替える。

### フェーズ遷移

```
FOLD_BUILDING ──[折り返し検出]──→ CHAIN_TAIL ──[標準発火点から3連鎖以上]──→ COMPLETION
```

| フェーズ | 条件 | 目的 |
|----------|------|------|
| `FOLD_BUILDING` | GTR未検出 | 折り返し構築に集中 |
| `CHAIN_TAIL` | 折り返し検出済み & 標準発火点からの連鎖 < 3 | 連鎖尾を伸ばす |
| `COMPLETION` | 折り返し検出済み & 標準発火点からの連鎖 >= 3（作業版では検証済みの限定頭伸ばしも対象） | GTR仕上げ |

右側のぷよ数だけでは消去順を表せないため、個数によるフェーズ遷移は廃止した。
限定頭伸ばしの仕込みは表示上も不足色を明記し、このフェーズ名を発火可能・完成の証拠にしない。

### フェーズ別重み（ADVISOR_WEIGHTS）

| スコアラー | fold_building | chain_tail | completion |
|------------|:------------:|:----------:|:----------:|
| foldProgress | **4.0** | 0.5 | 0.2 |
| chainTail | 0.3 | **1.0** | **1.0** |
| connectivity | 1.0 | 1.0 | 1.0 |
| heightPenalty | 1.5 | 1.0 | 1.0 |
| chainSim | 0.0 | **5.0** | **5.0** |

`fold_building` では `foldProgress` が支配的（×4.0）で、折り返し構築を最優先する。`chainTail`は0.3倍で残し、折り返しに直接使えない相方も後ろへ活用する。
候補配置後の盤面からY字の配色を再評価するため、折り返しと同じ横置きの相方が`(2,最下段)`へ入る場合だけ、その実色を支持色Cとして採用する。それ以外の候補とD色は配置前の計画で評価し、右側へ置くためだけの都合のよい配色変更を許さない。
`chainSim` はGTR完成前には計算しない（0.0）。

## 2. GTRテンプレートマッチング

### テンプレート定義

GTRの折り返しは7つのターゲット位置で構成される。色A/Bは全12通り試行して最適を選択。

```
col:    0    1    2
       ┌────┬────┐
h-3:   │ A  │ B  │          ← 優先度3（P3）
       ├────┼────┼────┐
h-2:   │ A  │ A  │ B  │     ← 優先度2（P2）
       ├────┼────┼────┘
h-1:   │ B  │ B  │          ← 優先度1（P1）
       └────┴────┘
```

- **優先度1 (P1)**: 最下段 (0,12)(1,12) = 色B×2
- **優先度2 (P2)**: 中段 (0,11)(1,11) = 色A×2, (2,11) = 色B
- **優先度3 (P3)**: 上段 (0,10)(1,10) = 色A, 色B

### 色割り当て探索

```
scoreFoldProgress()
  ├─ 全12通りの(A,B)色組み合わせで evaluateTemplate() を呼ぶ
  ├─ 最高スコアを採用
  ├─ 全組み合わせが矛盾（-Infinity）の場合 → エリアペナルティのみ返却
  └─ bestScore + scoreFoldAreaPenalty() を返却
```

既存フィールドの色と矛盾する(A,B)組み合わせは即座に `-Infinity` で除外される。
例: (0,12)=赤 のとき (A,B)=(緑,青) は B=青≠赤 で矛盾 → -Infinity

### テンプレートマッチスコア

配置したぷよがテンプレート位置に着地した場合のスコア:

| 条件 | スコア |
|------|--------|
| P1正解 | +30 |
| P2正解 | +30 |
| P3正解 | +30 |
| 間違った色を置いた | **-50** |

### 前提条件チェック（構築順序の強制）

GTRは下から順に積む必要がある。上位の配置を急ぐと暴発リスクが生じるため、
前提が未充足の場合はボーナスに `PREREQUISITE_PENALTY (0.3)` を乗算する。

| 対象 | 前提条件 | 未充足時のスコア |
|------|----------|------------------|
| P2 | P1が全て正しい色 | 30 × 0.3 = **9** |
| P3 | **P1が全て正しい色** | 30 × 0.3 = **9** |

**P3の前提条件がP1のみの理由:**

P3は(0,10)と(1,10)であり、重力により直下の(0,11)と(1,11)が埋まっていなければ配置不可能。
つまりP3配置時点でP2位置は物理的に充填済み。色の正しさは`evaluateTemplate`の
矛盾チェック（-Infinity）が保証するため、P2色チェックは不要。
旧実装ではP2 col0-1の色正解を要求していたが、過剰に厳しくP3完成率を下げていた。

## 3. 折り返しエリアペナルティ

`scoreFoldAreaPenalty()` はテンプレートマッチとは独立に、
配置位置の「エリア」に基づくペナルティを加算する。

```
配置されたぷよの位置を判定:

  (0,h-4)          →  TRIGGER_BLOCK_PENALTY (-250)  標準発火口の保護（最優先）
  col0-2, y < h-3   →  TOO_HIGH_ON_FOLD_SIDE (-20)  高すぎる
                        ※発火口以外のP3直上(1,h-4)は P3_COMPANION_TOO_HIGH (-3) に軽減
  col0-2, (2,h-1) & 配置後にP1完了 & (2,h-2)空  →  STEPPING_STONE_BONUS (+15)  踏み台
  col0-2, (2,h-3) & P2(2,h-2)完了      →  CHAIN_TAIL_CONNECTION (0)  接続点
  col0-2, テンプレート外  →  NON_TARGET_FOLD_PENALTY (-7)  (2,10)等
  それ以外           →  OUTSIDE_FOLD_PENALTY (0)        ペナルティなし
```

| 定数 | 値 | 意味 |
|------|-----|------|
| `TOO_HIGH_ON_FOLD_SIDE` | -20 | col0-2でrow9以上に積む（折り返しが高くなりすぎ） |
| `TRIGGER_BLOCK_PENALTY` | **-250** | (0,h-4)の標準発火口を塞ぐ配置を強く減点 |
| `P3_COMPANION_TOO_HIGH` | **-3** | 発火口以外のP3直上(1,h-4)の相方のみ軽減 |
| `STEPPING_STONE_BONUS` | **+15** | (2,12)踏み台: 今回の配置でP1が完成する場合も適用し(2,11)到達を強力促進 |
| `CHAIN_TAIL_CONNECTION` | 0 | (2,h-3)連鎖尾接続点: P2(2,h-2)完了後はペナルティなし |
| `NON_TARGET_FOLD_PENALTY` | **-7** | (2,10)などテンプレート外の折り返しエリア |
| `OUTSIDE_FOLD_PENALTY` | 0 | 連鎖尾エリア（ペナルティなし） |

**`STEPPING_STONE_BONUS` の仕組み:**
(2,11)=Bを埋めるには(2,12)に先にぷよを置く必要がある（物理的な踏み台）。
しかし(2,12)はテンプレート外のため`NON_TARGET_FOLD_PENALTY`で忌避される。
配置後にP1が完成し、かつ(2,11)未充填のとき、(2,12)に+15のボーナスを付与し踏み台充填を強力促進する。
P1未完了時は通常のペナルティ(-7)を維持してP1構築の妨害を防ぐ。

**`P3_COMPANION_TOO_HIGH` の仕組み:**
P3へ縦置きすると相方がその直上へ入る。発火口ではない(1,h-4)は通常の
`TOO_HIGH(-20)`から`-3`へ軽減する。一方、A→(0,10)の上に相方を置く(0,9)は
標準発火口なので例外として`-250`を適用し、折り返し進捗だけで閉塞を推奨しない。

**`OUTSIDE_FOLD_PENALTY = 0` の理由:**
折り返し構築フェーズでも off-color のぷよは連鎖尾に積むべきであり、
エリア外ペナルティをかけると連鎖尾が育たず後半に苦しむ。

## 4. 連鎖尾スコア（scoreChainTail）

連鎖尾エリア（col 2-5）への配置を、Y字・座布団・L字の複数候補と実連鎖可能性から評価する。

### 研究背景

wata氏の[制約付き全探索](https://puyo-camp.jp/posts/158147)では、3〜6列目・下4段・4連結だけに限定して403形を列挙した。この条件と「バリエーション数を良型とする」定義ではY字が最多だった。

ただし、連結数を広げた[追加調査](https://puyo-camp.jp/posts/158531)では横3、4連鎖まで範囲を広げた[別調査](https://puyo-camp.jp/posts/159920)ではだぁ積み型が最多になった。したがって、これは対戦強度の固定ランキングではなく、条件付きの形の辞書として使う。

### スコアリング要素

| 条件 | スコア | 意味 |
|------|--------|------|
| 候補形の同色連鎖セルを新規充填 | +60/セル | 支持色が消えた後につながる同色セル |
| 候補形の床・支持セルを新規充填 | +24/セル | 上のぷよを浮かせず、後続の伸ばしにも使えるセル |
| 既存候補への継続 | +4/既存セル（最大3） | 毎手別形へ揺れず、進行中の形を優先 |
| 候補形充填後に標準発火で3連鎖以上 | +100 | シルエットだけでなく実際の消去順を確認 |
| 進行中の全候補を塞ぐ | -2500 | 既存の同色連鎖セルを別色で破壊 |
| 3-6列目の横方向同色隣接 | +8 | 接続点を含む横方向のグルーピング |
| 3-6列目で2色以上のレイヤー | +5/列 | 異なる色の層構造（連鎖の基盤） |
| y < h-4（高すぎる） | -10 | 不安定な高積みを抑制 |

### 形状名の扱い

`TailPlanner`はY字・座布団・L字を同じセル単価で比較し、形状名そのものには倍率や固定順位を付けない。
これは候補検出・汎用スコアの規則であり、5連鎖骨格探索の学習上の形別調整とは分離する。
Y字の従来教材ルートも候補として残し、各配置で適応型3候補との高い方を採用する。
適応型候補はGTR折り返し計画がまだ成立可能な盤面でのみ加点し、コアが崩れた局面では回避・復旧の評価を優先する。
支持セルは同色固定にせず、上の連鎖セルを支えながら後続へ回収できる床として扱う。
従来の `PlacementAdvisor.getCompletedTailShape`／`isAdaptiveTailComplete` の内部完成判定はテンプレート充填だけでは成立せず、標準発火点から3連鎖以上になるかをシミュレーションで確認する。これはプレイヤーの実発火済みを意味しない。認識済みの頭伸ばしを除いた基礎盤面で確認する場合があり、現全盤面が常に即発火可能だという保証でもない。ガイドの尾完成表示は別の `isGuidedTailComplete` が必要な実セル・キー待ち接続を確認する。[ゲームモード仕様](GAME-MODES.md)の尾基本形チェックと区別する。

| 候補 | 同色連鎖セル | 支持セル |
|------|----------------|----------|
| Y字 | `(2,h-1) (3,h-2) (4,h-2) (2,h-3)` | `(3,h-1) (4,h-1)` |
| 座布団 | `(2,h-3) (3,h-2) (4,h-2) (5,h-2)` | `(2..5,h-1)` |
| L字 | `(2,h-1) (3,h-1) (3,h-2) (2,h-3)` | なし |

Y字の連鎖色が既に始まっている場合は、折り返しと直結する`(2,h-3)`に同色を置く向きを優先する。そのセルを相方色で塞ぎ、未着手の別形へ切り替える候補には競合ペナルティを与える。

## 5. 同色連結スコア（scoreConnectivity）

配置後のグリッドで、配置したぷよを起点にfloodFillし、連結グループのサイズを評価。

| グループサイズ | 条件 | スコア | 説明 |
|----------------|------|--------|------|
| 4以上 | 構築中、または完成盤面の本線以外 | **-500** | 暴発（即消え）→ 構築ボーナスを打ち消す |
| 4以上 | 予約発火口・発火色・期待連鎖内容を満たす本線の発火色グループ | 0 | このグループだけ暴発ペナルティを免除。相方の独立消去は減点 |
| 3 | 縦3積み | -10 | 理想形の連鎖尾を阻害 |
| 3 | 折り返しエリア内（非テンプレート含む） | **-100** | 暴発リスク大 |
| 3 | その他 | +20 | 連鎖構築に有益 |
| 2 | - | +10 | 適度な連結 |
| 1 | - | 0 | 孤立 |

### 折り返しエリア3連結の判定ロジック（isFoldAreaGroup）

テンプレート位置**のみ**で構成される3-groupは正常なGTR構築なのでOK(+20)。
非テンプレート位置（(2,12)や(2,10)）を含む3-groupは暴発リスクとして-100。

```
例: OK（テンプレートのみ）
  A(0,11) + A(1,11) + A(0,10) → +20

例: NG（非テンプレート含む）
  B(0,12) + B(1,12) + B(2,12) → -100
  ※ (2,12)は非テンプレート → 次にB(2,11)が来ると4連結暴発
```

## 7. 連鎖シミュレーション（scoreChainSimulation）

`CHAIN_TAIL` / `COMPLETION` フェーズのみ有効（`FOLD_BUILDING` では0）。
まず、仮想単ぷよによる基準結果と、予約発火口・発火色・各連鎖ステップの元セルが一致した場合だけ本線発火とする。即時加点は基準本線の連鎖数・消去数に限定する。同じステップ・同じ色で基準セルを含む連結成分へ相方が加わる場合は本線の自然な拡張として許容し、基準セルを含まない独立成分や基準後の追加ステップだけを副次消去として減点する。構築途中の早撃ちや、完成盤面でも本線と無関係な消去は暴発として扱う。次に、その消去を解決した安定盤面から、全6列・全4色の仮想単ぷよ発火候補を探索する。
各候補は同時消去と重力を連鎖が止まるまで実行し、最大連鎖数と参加ぷよ数を評価する。
後半の仮想単ぷよ探索は実際に操作できる1手ではなく、盤面の接続可能性を比較するプローブである。
発火探索自体は特定の列を優遇しない。

| 条件 | スコア |
|------|--------|
| GTRパターン検出 | +10 |
| 連鎖1つにつき | +18 |
| 消去参加ぷよ1個につき | +0.35 |

## 8. NEXT/NEXTNEXT先読み（evaluateLookahead）

currentPairの配置を決定する際に、NEXTとNEXTNEXTを考慮する2手先読みシステム。

### 仕組み

```
currentPairの各候補配置に対して:
  1. gridAfterCurrent = 配置後に消去・重力を解決した安定グリッド
  2. 安定グリッドからフェーズを再判定する
  3. NEXTの全配置候補を軽量スコアリング（意図した本線発火だけを加点し、全色プローブは省略）
  4. 同じsimulateTurn結果の安定盤面を次段へ渡す
  5. NEXT上位4候補についてNEXTNEXTの全配置を評価
  6. bestNextScore = NEXT + NEXTNEXT×0.4 の最大値
  7. totalScore += bestNextScore × DISCOUNT(0.4)
```

### 設定

| 定数 | 値 | 意味 |
|------|-----|------|
| `LOOKAHEAD.ENABLED` | true | 先読みの有効/無効 |
| `LOOKAHEAD.DISCOUNT` | 0.4 | nextPairスコアの重み（currentの40%） |
| `LOOKAHEAD.SECOND_DISCOUNT` | 0.4 | NEXTNEXTをNEXT内でさらに減衰 |
| `LOOKAHEAD.BEAM_WIDTH` | 4 | NEXTNEXTを調べるNEXT上位配置数 |

### パフォーマンス

- 計算量: current各候補につき、NEXT約22候補 + 上位4候補×NEXTNEXT約22候補
- 先読みの形状評価ではchainSimを省くが、実ゲームと同じ盤面を渡すため各深度で消去・重力は解決する
- getAdviceはフレーム毎ではなく手駒確定時のみ呼ばれるため許容範囲

### DISCOUNT値の根拠

- 1.0だとnextPairが支配的になり、目前の折り返し進捗を犠牲にする
- 0.4は「next手に絶望的な配置（例: -200点）を避けつつ、current手の判断は維持」するバランス

## 9. スコア計算の具体例

以下は汎用評価の構成要素を説明する例であり、先読みや適応型連鎖尾評価を含めた
最終推薦スコアではない。骨格探索が適用される場合は、その探索結果が順位を決める。

### 例1: P1配置（最も基本的なケース）

手駒: BB（青-青）、フィールド: 空

```
配置: col0, rot→ (横右) → B(0,12) + B(1,12)

foldProgress:
  evaluateTemplate: P1正解×2 = +30 + +30 = +60
  areaScore: 0 (テンプレート位置)
  → 60
chainTail: 0 (col0-2)
connectivity: B(0,12)+B(1,12) = 2-group → +10
heightPenalty: 0
chainSim: 0 (fold_building)

小計 = 60×4.0 + 0×0.3 + 10×1.0 + 0×1.5 + 0
      = 240 + 0 + 10 + 0 + 0 = 250
```

### 例2: P3配置（相方が発火口を塞ぐケース）

手駒: AB（P3色A + off-color）、P1+P2(col0-1)完成済み

```
配置: col0, rot↑ (縦) → A(0,10) + B(0,9)

foldProgress:
  evaluateTemplate: P3正解 = +30 (前提充足: ×1.0)
  areaScore: (0,10)テンプレート=0, (0,9)TRIGGER_BLOCK_PENALTY=-250
  → 30 + (-250) = -220

fold_buildingでの折り返し項の寄与 = -220×4.0 = -880
（同色連結・連鎖尾・先読み等は別途評価）
```

比較: 同じ手駒を連鎖尾に配置した場合はchainTail評価を0.3倍で加える。配置候補に合わせてC/D配色を再評価するため、折り返しを進める横置きの相方も連鎖尾の支持ぷよとして評価できる。
→ 左側の折り返しを優先しつつ、相方を右側へ捨てず次の構築へ接続する。

### 例3: 間違った色をテンプレート位置に置くケース

手駒: GR、テンプレート A=赤, B=青

```
配置: col1, rot↑ → G(1,11) + R(1,10)

foldProgress:
  evaluateTemplate for A=R, B=B:
    G(1,11) needs A=R → G≠R → WRONG_COLOR = -50
    R(1,10) needs B=B → R≠B → WRONG_COLOR = -50
    → -100
  → -100 × 4.0 = -400

→ 大きな負値 → この配置は選択されない
```

## 9. -Infinity フォールバック

全12通りの(A,B)色割り当てが既存フィールドと矛盾する場合、
`bestScore` が `-Infinity` のままになる。

この場合、テンプレートスコアを無視してエリアペナルティのみで判定する。
これにより「折り返しが壊れた状態」でも連鎖尾への誘導が正常に機能する。

```typescript
if (!isFinite(bestScore)) {
  return areaScore  // テンプレートスコアを諦め、位置ペナルティのみ
}
```

## 10. 着地シミュレーション

`ChainSimulator.simulateLanding()` は各列について、盤面上端から落下して到達できる空行を探索する。途中に穴がある不整形盤面でも、既存ぷよを通り抜けて下の穴へ着地させない。
`simulateTurn()` は着地、仮配置、同時消去、重力、次連鎖を一括で解決し、着地直後の`placedGrid`と連鎖後の`stableGrid`を両方返す。推薦・GTR評価・計測スクリプトはこの共通結果を使う。実ゲームは同じモジュールの`clearConnectedPuyos()`と`applyGravity()`を同期的に反復し、解決後の最終盤面を描画へ反映する。

| 回転 | sub位置 | main位置 |
|------|---------|----------|
| 0（↑） | main の上 | 到達可能な空行 |
| 1（→） | main の右列 | 各列独立に到達可能な空行 |
| 2（↓） | main の下 | 到達可能な空行-1 |
| 3（←） | main の左列 | 各列独立に到達可能な空行 |

列範囲制限:
- rot0/2: col 0-5
- rot1: col 0-4（subが右にはみ出さない）
- rot3: col 1-5（subが左にはみ出さない）

## 14. GTR連鎖尾の研究背景

### 参考動画

[【ぷよ研究】GTRの後ろの形を分析してみました](https://www.youtube.com/watch?v=TlVwMVFA2co) を主資料にする。
GTR後ろ3連鎖、各4連結、3〜6列目の下4段という条件は、本アプリの低い土台に近い。
作者の報告は403パターンだが、未検算との留保があり、本アプリでも全図を転記・検算していない。
確認範囲は自動字幕全編と選択した時刻の図で、全編連続視聴ではない。

### 最初の調査におけるバリエーション数

確認した図の派生数はY字57、横3型49、L状の例37。これは動画の制約内での件数であり、勝率や実ツモの完成率ではない。
[4連鎖バージョン](https://www.youtube.com/watch?v=WHb6pKYrv_0) は尾4連鎖・4〜6列目5段目も使う別条件で、順位も変わる。
補足動画の高い尾の順位を、本アプリの低い5連鎖土台の優先順位へそのまま移さない。

### 設計への反映

1. **完成優先**：教材方針はY字→座布団→L字だが、進んだ別形や今完成できる手を、型の名前だけで見送らない。
2. **近い派生を残す**：本書冒頭の条件で、完全同等な候補の次の配色の受け方を比較する。新しい数値加点や未知ツモの確率ではない。
3. **教材を分離**：完成3図は表示用。手動閲覧で推薦を誘導せず、表示例を実盤面の達成実績へ加えない。
4. **実接続を検証**：支持の消去順と落下後の接続を共通物理で確認する。形の一致や列高だけで完成とはしない。

設計の不採用案・500ゲーム比較・動画時刻は [学習と実装記録](../records/GTR-COMPLETION-VIDEO-20260927.md) に保存する。

## 15. 人間の手順との比較とちぎり抑制

公開の配置付き記録500本を同盤面・見えている3組だけで比較する仕組みを追加した。
対象の年代・先後折り・検証用の分割と結果は[人間手順の調査記録](../research/GTR-HUMAN-PLAY-STUDY.md)を参照。

自由形の現在手と次2組の評価では、横置きの着地段差に対して
`splitDropCost = min(abs(mainY - subY), 3) * 8` を減点する。縦置きと同じ高さの横置きは0。
定義は `src/game/advisor/PlacementEffort.ts`。これは操作時間の実測モデルではなく、小さな構築上の選好である。
有用なちぎりを禁止せず、完成5連鎖の物理検証済み発火優先を維持する。
`FiveChainPlanner` の教材探索のスコアは変更していない。
