# 文書整理で見つかった説明の矛盾と根拠

調査日：2026-10-03。Astraが候補を確認し、資料は親担当が再取得して読んだ。
ゲーム実装の現状、ゲーム一般の資料、当時の変更履歴を分けて判定する。
今回の範囲は文書の訂正であり、乱数・ツモ順・推薦・採点は変更しない。

## C1 初手の分類・抽選と適用範囲

旧PUYO-GENERATION.mdはAAAAを含む5種類を各20%で生成し、実際のゲームに準拠すると説明していた。
旧REQUIREMENT.mdとCLAUDE.mdにもAAAAを含む現行仕様の記述があった。
しかし、現行 `src/game/core/PuyoPair.ts` の `createValidTwoHandCombination` は、
AAAAを練習目的で除外し、AAAB、ABAB（AABBを含む）、ABAC、AABCの4分類から選ぶ。
各分類の選択区間は25%。これはコードの抽選幅であり、今回の出現頻度実測ではない。

ガイドは初期2手のみ制約付きで、3手目以降は独立に色を抽選する。
スコアアタックは初期2手制約付き・3手目ランダム、その後は制約生成のpair1だけを使う。
生成したpair2との組ではないため、後続の隣接2手が常に最大3色になる保証はない。
根拠：`src/game/scenes/GuidedPracticeScene.ts` のcreate／placeCurrentPair／spawnNextPair、
`src/game/scenes/PuyoGame.ts` のcreate／placeCurrentPair／spawnNextPair。

### 外部資料の再確認

| 資料 | 今回確認できた内容 | 根拠の範囲・限界 |
|---|---|---|
| [ゆーふぉ「先折りGTR土台の初手手順攻略」](https://puyo-euphonic.com/gtr-first-procedure) | AA BB≒AB AB、AA AB、AB AC、AA BCという学習上の4分類 | 筆者の教材。実ゲームの全初手や等確率抽選を証明する資料ではない |
| [ケーケー「65536通りの配ぷよの初手パターンを解析して思ったこと」](https://puyo-camp.jp/posts/139864) | 筆者自身の配ぷよ解析にはAA AAも含まれ、分類ごとの件数は均等ではない | 非公式の個人解析。記載値を本ツールの測定結果や全作品共通仕様にしない |
| [配ぷよ検索・制作者による生成方法の説明](https://puyotsumo.oiu-piponeer.com/) | 対戦の開幕2手は最大3色で1色の場合もあり、チャレンジとは生成方法が異なると説明 | 非公式ファンツール。上の解析と同じ対象を扱うため独立した実機検証件数として加算しない |

資料の本文を再取得して確認した。SEGAの公式な配ぷよ仕様書を確認したものではない。
異なる作品・ルール・モードについてAAAAの可否を一律に断定しない。
今回は上記の資料で判断できたため、追加動画の視聴・字幕取得・全編視聴は行っていない。

**判定：本製品の実装説明を4分類へ訂正し、練習用抽選と実ゲームの配ぷよを区別する。**
訂正先：PUYO-GENERATION、REQUIREMENT、GAME-MODES、CLAUDE。
元のメモは履歴として保持し、現行仕様への注意を付ける。

## C2 完成見本・配色・採点の古い現行説明

CLAUDEの「現在の実装状況」にはY字・L字・階段型の見本とA→赤などの固定配色、右上使用の加点が残っていた。
現行 `src/game/guide/GTRCompletionExamples.ts` はY字・座布団・L字で、A/Bは折り返しの役割に合わせる。
4記号を異なる色に保ち、C/Dは残りの色を使うため、記号の配色は固定ではない。
採点版 `masked-foundation-minimal-v2` は右端位置だけの加点を廃止し、評価範囲内の最小19個による
基本形2連鎖から始まる5連鎖・全消しなどを100点条件とする。

根拠：[視覚ガイド](../specs/GTR-VISUAL-GUIDE.md)、[現行採点仕様](../specs/GTR-SCORING-SYSTEM.md)、
[2026-09-27の設計・検証](../design/GTR-SURFACE-QUALITY-20260927.md)、現行の教材・採点コード。
これは外部の技法の正否ではなく、本ツールの受入済み変更を現行説明へ反映できていない問題。
外部記事や動画で本ツールの実装状態を決めず、上記の実装と検証記録を正とする。

**判定：CLAUDEとGAME-MODESの現行説明を揃え、当時の採点設計・測定結果は保持する。**

旧GTR-PATTERNSの完成例は旧教材データの参考例であることを明記し、現行3図や100点保証と区別する。

## C3 現行の非発火ガイドと旧実発火70%基準

REQUIREMENT冒頭の2026-09-19追補は、本線5連鎖以上の実発火率70%以上を品質要件として掲げていた。
その後、2026-09-24の利用者指定で、完成後も自動発火を勧めず土台を保って伸ばすガイドへ変更している。
[現在の品質基準](../specs/GTR-QUALITY-CRITERIA.md)は土台内5連鎖70%超を目標とし、
旧方式の実発火率・余り条件を別の診断として明記している。
要件入口にもこの区別を反映し、旧9/19の指定と測定は当時の履歴として残す。
500局の場合、70%以上は350局以上、70%超は351局以上であり、同じ条件に読み替えない。
これは利用者指定の製品契約で、外部の教材や動画を根拠に上書きしない。

**判定：REQUIREMENT冒頭で現在の目標を先に示し、旧診断基準を明確に分離する。**

## 旧教材例と現行実装の区別

旧REQUIREMENTは結果の「連鎖尾タイプ」と、Y字・L字・階段形の高さ分類を実装済みと記載していた。旧図の10/11/12行ラベルは上から0始まりの実装配列indexに対応し、現行文書の上から1始まりでは11/12/13行目になる。図と旧分類の本文は履歴として残す。
現在の教材と推薦は `TailPlanner`・`TailShape`・`GTRCompletionExamples` にあるY字・座布団・L字を扱う。一方、採点器 `src/game/gtr/GTRPatterns.ts` は `chainTailType` を `undefined` としており、形状名を確定せず土台内連鎖などを評価する。[視覚ガイド](../specs/GTR-VISUAL-GUIDE.md)と[採点仕様](../specs/GTR-SCORING-SYSTEM.md)を現行説明とする。

旧GTR-PATTERNSはAAAAを「別ルート」とする初手教材文と、ABACを「2色含み」とする見出しを持っていた。前者は練習用の分類・配置例であり、現行の推薦の固定手順や `GuideManager` の専用経路ではない。現行の通常初期2手生成はAAAAを除外しているが、外部ゲーム全般への断定はしない。後者のABACはAが2個、B・Cが各1個の3色関係なので、見出しを訂正した。旧配置例や教材研究の採否は保持する。[現行の生成仕様](../specs/PUYO-GENERATION.md)を参照。

GAME-MODESの共通GTR評価欄にも、ガイドのY字・座布団・L字の尾候補評価が混在していた。共通採点器の `chainTailType` は形状名を確定せず、折り返し・評価範囲内の土台連鎖・最小完成・余りを評価する。ガイドの `isGuidedTailComplete` は別判定で、キー待ち接続を含むため、尾基本形チェックだけで実発火・土台内5連鎖・100点を保証しない。この違いを[ゲームモード仕様](../specs/GAME-MODES.md)の詳細チェックと共通評価欄の両方へ反映した。2026-09-27の完成見本などの更新は当時の記録として保ち、2026-10-03は文書説明のみを訂正した。

GTR-PATTERNSとPLACEMENT-ADVISORの旧説明は「尾の完成には標準発火からの実連鎖」を無限定に述べ、ガイド表示まで同じ条件に見せていた。`PlacementAdvisor.getCompletedTailShape`／`isAdaptiveTailComplete` は内部判定として発火シミュレーションを行い、認識済みの頭伸ばしを除いた基礎盤面を使う場合がある。`isGuidedTailComplete` は実セルとキー待ち接続を確認する別のガイド判定であり、プレイヤーの発火済みを意味しない。[尾基本形のチェック](../specs/GAME-MODES.md)との関係を両仕様文書に明記した。

旧REQUIREMENTの800×800pxガイド、600×800pxスコア画面は、現行のReactラッパーと `VisualConfig`・シーン描画に合わない。現在はガイド全体900×800px／右側COACH 380×624px、スコア画面640×800pxで、旧数値は当時の記載として保持する。また旧UI欄の「サイドメニュー常時表示」「TOPページに開発予定案内」は、現在の `MainLayout`・`Header`・`SideMenu`・`TopPage` と異なる。広い画面はメニュー常時表示、狭幅はヘッダーのボタンで開閉し、対戦・統計の予定はサイドメニューの「SOON」で案内する。現在のTOPに予定一覧はない。[要件の現行説明](../specs/REQUIREMENT.md)へ反映した。

CLAUDEの旧実装一覧は、2026-10-03の文書訂正が旧い完了・予定表記に混在しており、章全体を現在の完了状態と誤認しやすかった。旧本文の記録は残し、現行資料への入口と保存範囲の注意を付けた。旧UI構成も当時の画面記録として区切る。`App.tsx` は `TopPage.tsx` を表示し、旧 `TopMenu.tsx` のSupabase接続状態表示は現行ホームにない。ただしSupabase自体の接続成否は今回確認していない。`Header.tsx` はアカウントを準備中と示し、現行SideMenuにフリープレイ項目はない。`PuyoRenderer.ts` はアトラスを読み込みフレームを登録する。[現行コード構成](../PROJECT-STRUCTURE.md)と[ゲームモード仕様](../specs/GAME-MODES.md)を正とする。

旧一覧のCOACH「X座標380px」は位置と幅を混同していた。`VisualConfig.ts` の `GUIDE_X=690` は中心Xで、`GUIDE_WIDTH=380`、左辺は500px。`GuidedPracticeScene` はその中心をコンテナ位置として使うため、現行の説明を中心・幅・左辺に分けた。

当該動画の既存部分確認記録は保持し、今回は再視聴済みとは記録しない。
逆折りは現行製品の対象外という範囲を正とし、難易度についての一般的な断定は加えない。
