## 次回の調査での使い方

1. まず目録と既存 `id`・出典・試合重複キーを確認する。同じ譜面を重複収集せず、観測メモを追記する。
2. 保存済みの符号化ぷよ譜を `src/benchmark/HumanReplay.ts` で復元する。色の置換は同色関係を保つ。
   現在の読み取り処理の対象は空盤面開始・2個組・4色の記録。おじゃま等を含む映像全体の完全再現とは区別する。
3. 読み取れない手や対戦事情が重要な局面だけ動画へ戻る。URLと秒数、確認できた手数・盤面の範囲を保存する。
4. 気になった局面を `case-template.json` から作り、`observations/<安定したID>.json` として保存する。
   `isTemplate` は外し、目録の `observationFiles` へ登録する。未確認は `null` / `unverified` のまま残す。
5. 人間の手・現在ガイド・考えられる別案を**同じ盤面、同じ現在/NEXT/NEXT2**で比較する。
   譜面に後のツモが記録されていても、その時点で見えていないツモを推薦の入力に渡さない。
6. シミュレーションの結果、条件、コード指紋、反例を別途保存し、観測と改善案の採否を分ける。
   判断が変わっても元譜面や古い分析を黙って上書きしない。

既存の同盤面比較はプロジェクト直下から再実行できる。結果は毎回別名で保存する。

```sh
bun scripts/human/compare-human-openings.ts all benchmarks/results/human-comparison-<日付・版>.json benchmarks/human/gtr-openings-500-v1.json
```

この比較は最大12手・最初の消去前までであり、発火点伸ばしや右側の後半の成長を十分に評価しない。
その分析には後半の観測事例を追加する。現在の検証用101本も結果を見ているため、今後は固定回帰集合として扱い、未使用標本とは呼ばない。

## 記録する内容と判断の区別

- **観測**：元譜面、盤面、ツモ、配置、出典、動画時刻、確認範囲、読み取り確度。
  盤面は上から13行×左から6列、列は0始まり、回転は0上・1右・2下・3左。色の正規化の有無を条件に記す。
- **状況**：相手の攻撃・おじゃま・時間制約。分からなければ不明。意図は本人の発言など根拠がなければ推測と記す。
- **仮説**：色の受け入れが狭い、L字へ偏る、右端が低く伸ばしにくい、相方が余る等。反例も集める。
- **検証**：別案との成立性、完成率、ツモの活用、ちぎり、成長余地。状態は未評価・調査中・採用・不採用・判断保留を区別する。

`validation.status` は `unassessed / investigating / accepted / rejected / inconclusive` とする。
`accepted` は「この条件で改善案を採用した」という意味で、譜面全体や人間の一手を普遍的な正解にする意味ではない。
`isCorrectMoveLabel` は `false` を保ち、一致率だけを最大化する教師データに転用しない。

異なる手は直ちに不正解ではない。先折り・後折り、対戦と練習、見えている情報の違い、転記ミスも確認する。
**よく見られる手順という証拠と、その手順がこの練習目的に有効という証拠は別物として残す。**

## 保全

原資料の2ファイルは変更せず保持し、指紋をテストする。転記修正時は新しい版と変更理由を作る。
この2ファイルは `.gitattributes` で改行の自動変換を止め、環境変更だけで指紋が変わらないようにする。
派生データには元の `datasetId` / `recordId` と条件を残す。重複の代理キーは同一試合の完全な証明ではない。
新しい元譜面を増やす場合は、別の版付きデータセットを保存してから目録へ登録する。
ゲーム本体の採点ロジックからこの資料群を直接読ませない。
